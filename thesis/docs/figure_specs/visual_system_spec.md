# Thesis Figure System Spec

### 目标

这份 spec 用来统一论文前三章的图像系统，并为后续逐图重画提供约束。当前论文中最强的图像方向不是黑白框图，而是具有物理对象、流程结构、数据入口和公式关系的彩色解释图。后续重画应以这种解释力为目标，但要去掉 `fig_sim_pipeline.pdf` 里仍然存在的临时占位、英文中文混杂、元素拼贴感和局部拥挤问题。第四章结果图这轮先不讨论，等前三章的叙事图和方法图打磨完成后，再单独进入第四章结果图 spec。

前三章中的每张图都必须回答一个明确问题。绪论图负责回答“为什么选择这条链路”；方法图负责回答“连续时间物理对象如何变成可计算结构”；模型图负责回答“哪些自由度被显式保留，哪些过程被推回测量侧”。不能只把名词放进方框，也不能用通用示意替代本文实际模型。

### 统一图像语言

全篇图像应采用同一套视觉语法。物理链路和装置流程使用带有轻量图标感的彩色块，状态侧过程使用偏蓝或青绿色，测量侧过程使用橙色或红色，校准或参数约束使用淡黄色，最终指标和输出使用紫色或深色中性块。背景保持白色或极浅灰，箭头只表达真实的数据流、物理传播或算符推回方向。装饰性箭头、没有明确语义的连线和只为填满空间而存在的节点都应删除。

文字应尽量使用中文，保留 `QFC`、`BSM`、`POVM`、`MPS`、`TEBD` 等通用缩写。图内标题不应重复图题，也不应出现 `placeholder`、`rows=...`、`window ns=...` 这类内部实现元信息。若运行参数确实影响结论，应在图注或正文中以论文语言说明。

每张图应优先使用面板式结构。面板标签使用 `(a)`、`(b)`、`(c)`，每个面板只承担一个局部问题。多面板图的图题应说明面板之间的因果关系，而不是仅罗列面板名称。图中公式只在能锚定核心映射时出现，不能把公式当成装饰块。

### 章节图像主线

第一章应从应用压力走向链路选择。图像主线应依次说明量子接口在模块化量子计算中的位置、为什么远程纠缠产生是本文关注对象、为什么选择双光子 BSM 方案，以及为什么 QFC、长光纤和噪声受限区间构成建模动机。第一章图像不应堆叠多个抽象分类图，而应把“任务边界、体系结构位置、方案选择、物理链路”压缩成少数强图。

第二章应从连续时间物理对象走向张量网络计算对象。图像主线应展示连续输出场如何离散成时间 bin，时间 bin 如何排成双臂 MPS 链，当前时间窗如何决定局部门作用位置，TEBD 和 SWAP 如何在链上推进。当前若只显示一条通用 MPS 链或通用 brick-wall 门序列，就不足以说明本文的实际计算结构。

第三章应从物理链路走向实现分工。图像主线应展示显式保留的局域自由度、QFC 与滤波记忆如何嵌入时间 bin 链、光纤和探测网络如何通过对偶映射推回为输入端效应算符，以及单次任务在代码中如何分成状态侧演化和测量侧统计。第三章图像必须避免重复第二章的抽象方法图，也不能把实验装置、代码流程和公式关系无层次地拼在一张图里。

第四章暂不进入本轮 spec。第四章结果图大多已有数据基础，且重画方式依赖前三章是否已经建立统一的视觉语言。等前三章完成后，再单独讨论第四章的标定流程、时域波包、HOM/BSM、条件态、距离扩展、器件参数平面、误差预算和复杂度图。

### 合并与重画关系

以下条目按图片在正文中的首次出现顺序组织。后续逐图 spec 也应沿用这一顺序，先处理第一章，再处理第二章和第三章，避免在讨论中按问题严重程度跳来跳去而破坏论文叙事线。本轮不讨论第四章图片的合并与重画。

`fig:interface_tasks` 和 `fig:arch_to_interface` 应合并为一张第一章总入口图。新图可以命名为 `fig_ch1_scope_architecture`，结构上从“量子应用压力”流向“模块化/分布式体系结构”，再流向“量子接口任务边界”。远程纠缠产生应作为主分支高亮，态转移、量子存储、远程门和错误探测作为旁支弱化。这样可以保留任务分类信息，同时避免两张黑白框图连续出现却只重复“量子接口很重要”这一层含义。

`fig:single_vs_two_photon` 应与 `fig:link_overview` 形成一张更强的链路选择图，而不是继续保留当前过于简单的黑白方案图。新图可以命名为 `fig_ch1_scheme_and_link`，上半部分或左侧面板比较单光子方案和双光子方案的关键约束，下半部分或右侧面板展示本文采用的 Rb 原子、腔、QFC、电信光纤、中继站 BSM 和探测链路。当前 `fig:link_overview` 的彩图解释力应保留，但应统一中文标签和视觉样式。当前 `fig:single_vs_two_photon` 中箭头穿字、节点关系含混的问题应彻底重画。

`fig:noise_vs_distance` 在第一章承担外部文献动机，说明远距离下信号衰减与背景噪声的相对变化。本轮只判断它在绪论中是否必要，不把它与第四章自有距离扫描结果放在同一轮合并讨论中。若保留，应明确它是文献趋势图，不参与本文数据闭环；若后续第四章结果图足够强，再考虑用自有结果替代它的动机功能。

`fig:ch2-timebin`、`fig:ch2-mpschain` 和 `fig:ch2-tebd` 应合并为一张第二章核心方法图。新图可以命名为 `fig_ch2_timebin_mps_tebd`。第一面板展示连续时间输出场被切成时间 bin；第二面板展示双臂链路在 MPS 中的站点顺序，包括发射体、A/B 两臂时间 bin、滤波记忆模和当前活跃窗口；第三面板展示一个时间步内的局部门、SVD 回写和 SWAP 调度。现有 `fig_mps_chain.pdf` 只有四个抽象站点，不能正确说明实际情况，应被替换。现有 `fig_tebd_pattern.jpg` 只是通用 TEBD 示意，也应被吸收进新图。

`fig:ch2-duallane` 不应直接删除，但它应降格为第二章的概念分工图。它只负责说明状态侧和测量侧为何可以分开，不负责展开所有装置细节。后续 `fig:ch3_effect_pushback` 是它的数学放大图，`fig:sim_pipeline` 是它的实现放大图。三者需要形成父图和子图关系，而不是三张重复流程图。

`fig:ch3_effective_dofs` 应保留并重画为局域自由度图。新版本应补充 3 维滤波记忆模，并明确 4 维原子块、三维腔偏振截断、5 维时间 bin 和 3 维记忆模之间的关系。它不应与 `fig:sim_pipeline` 合并，因为它回答的是局域建模口径，而不是全局执行顺序。

`fig:ch3_effect_pushback` 应保留为测量侧推回图，但需要与 `fig:ch2-duallane` 统一配色和术语。它可以继续用输入端、光纤信道、分束器和四路探测器的链式结构，但应减少混合中英文，并让虚线反向箭头更清楚地表达对偶映射方向。

`fig:sim_pipeline` 必须重建。当前图虽然接近目标彩图风格，但含有明显临时占位和拼贴结构，不能作为论文终稿图。新图应吸收 `fig_sim_pipeline_old.pdf` 中清晰的双泳道结构，同时使用更接近彩图的物理对象和数据对象。新图应明确分成“状态侧演化”和“测量侧统计”两条泳道，并在末端汇合为条件概率、条件态、保真度、CHSH 和速率等输出。它不应再把实验装置图、MPS 三维块、矩阵热图和公式框随意堆叠，而应服务于“单次任务执行路径”这一问题。

### 行文配套变化

图像系统重画之后，正文也需要相应改变。正文不能继续把图当作段落后的附属说明，而应让每张图成为论证节点。每张图出现前应有一段明确说明读者此时遇到的问题，图出现后应有一段解释图中最关键的关系如何推进下一步论证。图题负责概括图的内容，正文负责解释这张图为什么在这里出现，以及它如何连接前后章节。

第一章的行文需要从“分类罗列”改成“链路选择论证”。`fig:interface_tasks` 和 `fig:arch_to_interface` 合并后，正文不应先单独介绍接口任务分类，再隔几十行介绍模块化体系结构。更合适的写法是先说明可扩展量子计算为什么产生模块化压力，再说明跨模块纠缠资源为什么把量子接口推到核心位置，随后用合并后的图把任务边界和体系结构位置一起交代清楚。这样第一章开头的图不再只是概念树，而是承担“本文为什么研究远程纠缠接口”的入口功能。

`fig:single_vs_two_photon` 和 `fig:link_overview` 重构后，正文应减少对单光子方案和双光子方案的并列散讲，把重点放到“为什么本文选择双光子 BSM 方案”这一判断上。图前段落应提出选择标准，例如长光纤相位稳定性、两臂不可区分性、宣告成功率和中继站实现复杂度。图后段落应直接落到本文链路，把 Rb 原子、腔、QFC、电信光纤和 BSM 作为后续建模对象，而不是再次重复图中的所有器件名称。

`fig:noise_vs_distance` 若保留，正文应明确它是外部文献动机图，而不是本文仿真结果。它前面的段落应说明远距离链路为什么会从效率受限转向噪声受限，它后面的段落应把这个趋势转化为方法需求，也就是为什么不能只用效率连乘模型，必须建立包含时间窗、背景噪声、条件测量和后验态的端到端模型。

第二章的行文需要从“逐个介绍通用概念”改成“把物理链路翻译成计算结构”。`fig:ch2-timebin`、`fig:ch2-mpschain` 和 `fig:ch2-tebd` 合并后，正文应减少对外部 time-bin 图和通用 MPS 链图的依赖。合并图前应先给出连续时间场、时间分箱和局域相互作用的核心数学定义；合并图后应解释图中三个面板如何分别对应离散化、链式排布和局部门推进。这样读者看到的不是三张松散的教材图，而是一条从物理对象到算法对象的转换路径。

第二章中关于 TEBD 调度的正文也应随图改变。现有文字若继续只列发射、QFC、滤波和测量四步，会显得像流程清单。重画后的图应让正文更强调“为什么这些操作能保持局域性”，例如当前时间 bin 只与发射体或记忆模发生作用，SWAP 的作用是移动相邻关系，SVD 回写的作用是控制键维增长。正文应围绕局域性、因果顺序和可收缩性组织，而不是围绕软件步骤罗列。

`fig:ch2-duallane` 保留后，正文应把它定位为第二章的方法分工总图。图前应说明纯态 MPS 和测量侧效应算符推回分别解决什么成本问题。图后应明确这个双通道分工会在第三章被落实为具体局域自由度和具体测量链路。这样 `fig:ch2-duallane` 不会和第三章的推回图、流程图重复，而是成为二者的上位解释。

第三章的行文需要从“模型细节堆叠”改成“实现口径逐层落地”。`fig:ch3_effective_dofs` 重画后，正文应先提出一个具体问题：端到端模型必须显式保留哪些自由度，才能同时表示原子、腔、波长转换、滤波记忆和时间分箱。图后正文应逐项解释局域维度为什么这样选，哪些自由度被显式保留，哪些损耗或模式失配被参数化处理。若图中补入 3 维记忆模，正文也应同步把记忆模从表格中的一项变成图文共同解释的建模对象。

`fig:ch3_effect_pushback` 的行文应服务于一个数学转折：探测端的线性光学和探测响应不在态端逐步传播，而是通过对偶映射推回输入端。正文应在图前完成对偶信道公式的铺垫，在图后解释光纤 Jones/Kraus、分束器和探测器 POVM 分别如何改变效应算符。这样图中的反向虚线箭头才不是装饰，而是公式与代码实现之间的桥。

`fig:sim_pipeline` 重建后，正文应把它放在第三章末尾作为前三章方法的总收束。图前段落应说明它不是物理装置图，而是单次仿真任务的执行路径。图后段落应解释状态侧演化和测量侧统计如何在输出端汇合，并把这些输出连接到第四章的波包、窗口、HOM、BSM、保真度、CHSH 和速率结果。这样第三章结尾能自然转入第四章，而不是只在图题里堆叠流程名。

整体上，正文修改应减少“如图所示”之后的重复描述，增加图前的问题设置和图后的结论提取。若图中已经画出器件、箭头和流程，正文就不应再逐字复述它们，而应解释为什么这些结构重要、哪些假设由此固定、后续章节会如何使用这个结构。这样图和文字会形成互补关系，而不是互相重复。

### 后续逐图 spec 规则

后续每张图都应写单独 spec。单图 spec 需要说明它在正文中的位置、它必须回答的问题、它必须出现的对象、它不应出现的对象、它与前后图的分工、建议面板结构、图题应强调的结论，以及验收标准。验收标准应包括内容正确、无临时文本、无箭头穿字、无无意义方框、风格与全篇一致、正文引用和图题能够准确解释图中信息。

下一步应按正文出现顺序写逐图 spec。第一轮从第一章开始，依次处理 `fig:interface_tasks`、`fig:arch_to_interface`、`fig:single_vs_two_photon`、`fig:link_overview` 和 `fig:noise_vs_distance`；第二轮处理第二章方法图；第三轮处理第三章模型与实现图。若某张图特别严重，例如 `fig:sim_pipeline`，可以在讨论中重点标注，但文档组织仍保持正文顺序。第四章结果图等前三章完成后再开新 spec。
