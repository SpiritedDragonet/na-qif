## 1) 你这套仿真“实际在做什么”（非常关键）

### 1.1 发射：MPS + TEBD（collision model）是“真的在态上演化”

发射部分确实在 Schrödinger 图像下直接对 MPS 做两体门，得到两臂光场（时间仓链）与原子纠缠态：

- 两原子初态置于 `|u>`（索引 3），时间仓 bin 维度 5（vac, H780, V780, H1517, V1517），原子维度 4（|0>,|1>,|e>,|u>）
- 每个时间步对 `(bin, atom)` 施加 `emission_gate`（20×20 幺正），其形式是 `exp( √dt (L b† − L† b) − i dt H_sys )`
- 你用 swap 把原子在链上“搬运”，从最右侧 bin 开始依次与 bin 相互作用，最后把两个原子放到最左侧（site 0,1），后面依次是 A1,B1,A2,B2...

这部分逻辑自洽，属于“主干”。

------

### 1.2 QFC / 滤波 / 光纤 / 分束器：你现在基本都 **推到了 POVM（Heisenberg 图像）里**

这点特别重要，因为它决定你“哪些误差是在态里发生” vs “哪些误差是等价地揉进测量算符”。

- 在 `common.run_emission_to_bs` 里，QFC 与 780 滤波阶段只是“记录参数+调用 hook”，**并没有对 MPS 做任何门/信道**。你只是把 `qfc_theta_H/V` 固定设成 `π/4`，`apply_filter_780=True`，然后原样把 MPS 往下传
- `apply_fiber_channel` 也没有对 MPS 施加 Jones/损耗，它只是采样 `fiber_sample`（U_A/U_B/eta/pdl/phase/phase_slope 等），返回 “(mps, sample)”
- 真正把这些过程用上的地方在 `detection.run_detection_pipeline`：它构造 6D 输出端口的探测 POVM，然后按顺序把 POVM 往回拉：
  **E_out → U_BS† E_out U_BS →（投到 3D 单光子输入子空间）→ 光纤损耗/偏振/相位 →（嵌回 5D ledger）→ 滤波† → QFC†**

这在数学上是可行的（本质上是把通道合成到测量算符里），但它带来两个“把关点”：

1. **哪些噪声能安全地下推到 POVM？**
   只要它们是对光子子系统的局域 CPTP 通道（或幺正），且你最终只关心原子条件态和概率，推到 POVM 是等价的。你现在的 QFC、滤波、光纤 Jones、光纤损耗都符合这个前提
2. **但它会让代码读者误以为** “在 common pipeline 里真的做了 QFC/滤波/光纤”，其实没有。你自己也在 `single_run` 的 stage 文案里把它当成真实阶段了（会误导后续维护）。

## 2) 明确的“程序/逻辑实现”问题（优先修）

### 2.1 `enum_mode` 逻辑导致“no-dark 基线 vs dark 实际”比较永远算不出来

你在 `single_run._run_single_simulation_core` 里设计了：

- `enum_mode="no-dark"`：先 `p_dark=0` 枚举指标，再用 `p_noise` 只做抽样
- `enum_mode="dark"`：直接 `p_dark=p_noise` 枚举并抽样

但你后面计算 `p_false_approx = p_success_abs - p_success_no_dark_abs` 时：

- `no-dark` 模式里：`p_success_abs` 也是 no-dark 的（因为 `enum_main = enum_no_dark`），所以 `p_false_approx` 恒为 0
- `dark` 模式里：`enum_no_dark` 是 None，所以 `p_false_approx` 根本不算

也就是说：**不存在任何运行路径能同时得到 (dark 枚举) 和 (no-dark 枚举) 来做差**。这会直接破坏你想用“近似估计暗计数引入的额外成功率”的诊断目标。

**建议修法（低成本，强烈建议）：**

- 无论 enum_mode 怎么选，都做两次枚举：一次 p_dark=0（基线），一次 p_dark=p_noise（实际）。
  你可以让第二次只在需要输出对比指标时做，以节省时间。
- 或者加一个 `enum_mode="both"`，默认 both，这样你的“仿真指导实验”的可解释性会明显更好。

------

### 2.2 `fiber.noise_enabled=False` 并不能保证“光纤不再随机”

在 `_build_fiber_params` 里你确实把 `polarization_sigma/eta_std/pdl_sigma/phase_*` 都置零，但 **你没有改 `polarization_model`**，而 `channels._sample_jones` 对 `"haar"` 模型完全不使用 sigma——它仍会生成 Haar 随机 SU(2)

这导致：如果用户配置了 `polarization_model="haar"`，即使关掉 noise_enabled，偏振仍是随机的。这是明显的“参数语义 bug”。

**建议修法：**

- 在 noise_enabled=False 时强制 `polarization_model="fixed"` 或者直接令 `U_A=U_B=I`。
- 或在 `_sample_jones` 内部：如果 sigma==0 就直接返回 U_mean（对所有 model 一视同仁）。

------

### 2.3 `run_detection_pipeline` 会 **就地修改输入 MPS**（副作用风险）

`run_detection_pipeline` 一开始就对传入的 `mps._mps` 做了 `canonical_form_finite(renormalize=True)` 并把 `norm=1.0` 强行设定

这意味着调用方如果还想在后续对同一个 `mps` 做别的分析/演化，很可能被你悄悄改写了规范形式或数值。

**建议：**

- 最安全：在 detection 里对输入 MPS 做一次 `.copy()` 再规范化（你后面已经在 grouped-pairs 那边 copy 了，但 p_arrive 计算是在原对象上做的）。
- 或把这点写进 docstring/命名（例如 `run_detection_pipeline_inplace`），避免未来踩坑。

------

### 2.4 `DetectionEvent.site` 字段目前语义是错的/无用的（建议删或改名）

你在生成点击事件时这样设置：

```python
site_a = base_a if detector_a in ("H1","V1") else base_a+1
```

这等价于把输出端口 1 的点击“绑定到 A_n 这个 MPS site”，输出端口 2 绑定到 B_n。
这在物理上没有意义：输出端口是 BS 后的模式，是 A/B 的线性组合。你也没有在任何地方真正用这个 site 做计算（它只是跟着对象走）。

**建议：**

- 如果只是为了 debug：把字段改成 `output_port`（1 或 2），不要叫 site。
- 如果没人用：直接删掉，减少误导与维护成本。

## 3) 物理指标定义上最容易“误用/误解”的点

### 3.1 你现在的 `p_arrive` 统计的是“总共 2 个光子”，不是“每臂各 1 个光子”

`p_arrive` 来自一个 MPO 计数器，目标是整个光场（两臂所有 bin）里 “总光子数=2” 的概率

这有两个后果：

- 如果某一臂由于模型允许“多次发射”（跨多个 bin），另一臂没发射，你依然可能被计入 `p_arrive`，因为总数仍然是 2。
- 但实验上你真正想诊断的往往是：
  1. **每端各出 1 光子并都到达中站**（才有“正经 BSM”意义）
  2. 同端多光子导致的假符合 / 误投影概率

你现在把这些都混在 `p_arrive` 里，后续又拿它做 `p_success_given_arrival = p_success_true / p_arrive`
这会让指标很容易被误读为“给定两光子到达时的 BSM 成功率”，但它其实不是“每臂各一”的条件成功率。

**建议（非常建议加，实验指导意义大）：**

- 增加至少两个 arrival 计数：
  - `p_arrive_A1_B1`: A 臂总光子数=1 且 B 臂总光子数=1
  - `p_arrive_2_same_arm`: A=2,B=0 或 A=0,B=2
    然后分别给出对应的成功率与条件 fidelity。
    实现上：用类似 MPO 计数器，但分别对 A、B 子链计数，最后取 joint state (nA,nB)。这对定位“多光子污染 vs 暗计数污染 vs 光子不匹配”非常有效。

------

### 3.2 “true/false”的命名有歧义：你现在的 true/false 只区分“是否包含暗计数”

`SuccessEnumerationResult.p_success_true` 来自 `effects_true_by_bin`（不含暗计数分支），`p_success_false = p_success_all - p_success_true` 就等价于“成功事件里由暗计数贡献的那部分”

这没问题，但如果你要用它表达“真纠缠成功 vs 假成功”，那就不够：

- 同臂双光子、模式不匹配导致的伪投影，都会落在 `true` 里（因为它们不需要暗计数）。
- 这类是实验上更棘手、也更需要你仿真指导的“系统误差”。

**建议：**

- 保留现有 true/false（暗计数视角）没问题，但再加一层分类：
  - `signal_true`：每臂各 1 光子 + 无暗计数
  - `signal_contaminated`：由多光子/不匹配导致的成功
  - `dark_assisted`：暗计数参与
    这样你最后输出的 fidelity 下降才能对应“是哪类机理在杀你”。

------

## 4) 物理模型层面的“过度简化/缺项”——哪些会让仿真失去实验指导意义

下面我按“对 16 km 远程纠缠最可能主导 fidelity/成功率”的优先级来讲。

------

### 4.1 发射模型：你用的是 **有效 γ 的坏腔近似 + 单个输出链**（可能与高 finesse 场景不匹配）

你把 cavity-QED 复杂动力学压成一个有效发射率：

```python
gamma_eff = 2 * kappa_ex * (g / (kappa_ex + kappa_in))^2
```

并据此构造 jump L，然后用 collision-unitary 的方式发射到时间仓

这对应一种“马尔可夫、坏腔、可绝热消去腔模”的建模风格。
但你在需求里说“高 finesse 光学腔”：高 finesse 往往意味着腔线宽小（κ 小），不一定处在可绝热消去区域。那时：

- 腔模记忆效应、腔场与原子反复交换、发射波包形状可能显著不同
- 输出场可能不是简单的每步独立 collision

**这不一定意味着你必须上完整腔模（那会很重），但至少你需要确认：你的实验参数是否真在这个近似可用区间。**
如果不在，你现在这套发射子模块对“波包形状/多光子尾巴/相干性”的预测就可能偏离实验，进而 BS 干涉与 Bell fidelity 的趋势也会被误导。

**建议（按成本从低到高）：**

1. **先做标定式自检**：调 `gamma_eff`、`omega_peak`、`sigma` 使得你仿真的单臂发射强度分布（per_bin_prob）匹配实验测到的波包（或者腔输出的时间分布）。这能部分“把坏腔近似误差吸收进有效参数”。
2. 如果仍不够：把“腔内部损耗/自由空间自发辐射”作为额外未观测 jump（会导致原子退相干与成功率下降），至少用量子轨迹加入“泄漏通道”。你现在的 emission_gate 只有一个 L（其实是两极化合成），没有其它损耗通道

------

### 4.2 QFC：目前过于“理想 + 常数”，而且最关键参数不可配置

QFC 在你的模型里是一个 **每个 bin 上的幺正旋转**：

- 780 H ↔ 1517 H 角度 θ_H
- 780 V ↔ 1517 V 角度 θ_V

但在 pipeline 里 θ_H/θ_V 被硬编码为 `π/4`（50% 转换），而且没有进 `SimConfig`（用户无法扫参数），滤波永远开（780 永远被完全滤掉）

更关键的是：你对 QFC 背景噪声用“等效暗计数率”处理（`bg_rate_mean_hz/std_hz` → `p_noise`），这只能描述“随机点击”，不能描述噪声光子的 **多光子统计、与时间/频谱滤波的耦合**

**这会在什么情况下让仿真失去指导意义？**

- 当 QFC 噪声不是“极低概率、可近似成暗计数”的 regime，而是需要考虑：
  - 噪声光子占据时间窗的分布（与滤波器带宽/群时延有关）
  - 噪声导致的多点击/误投影
  - 噪声与信号在 BS 上的可区分性（可能降低 HOM 可见度）

**建议（强烈建议至少做到前两条）：**

1. 把 `qfc_theta_H/V` 和 `apply_filter_780` 放进配置（SimConfig），并能在 total_simulation CLI 扫。现在硬编码会让“实验参数扫描”失真
2. 噪声模型分两级：
   - 低噪声：保留你现在的等效暗计数（足够快）
   - 中噪声：至少扩展 bin 维度，使 1517 子空间允许“噪声 + 信号”形成 2 光子（否则你永远不可能出现“同一臂同一 bin 双光子”的噪声事件）。你目前 bin=5（单光子 ledger）在这方面是不够的

------

### 4.3 光纤：你有偏振/相位/PDL/损耗，但缺少 **色散/PMD/群时延失配**

你 fiber 参数已经覆盖了几类“慢漂移噪声”：

- 偏振随机 Jones（perturb / haar / euler）
- 总透过率波动 + PDL（eta_H/eta_V）
- 全局相位漂移 + 线性相位斜率（等效频差）+ per-bin 相位抖动

但对 16 km 光纤来说，影响干涉与符合判定的核心往往还有：

- **群速度色散（GVD）**：波包展宽 → 影响相邻 bin 的正交性、影响有效符合窗口
- **偏振模色散（PMD）**：H/V（或本征轴）之间出现时间延迟 → 等效成“偏振相关的到达时间差”，直接杀 HOM/BSM 可见度

你现在的模型没有任何“跨 bin 的耦合/卷积”（所有 bin 完全独立地被一个相位因子和一个 Jones 旋转处理），因此色散/PMD 这种“时间模式混合”完全缺失。

**建议（按实现成本）：**

- 低成本近似：
  - PMD：给 H/V 加一个相对 delay（以 bin 为单位的偏移或分布），或者给不同偏振施加不同的“time shift”相位因子（不只是全局相位）。
  - GVD：把单臂波包在 time-bin 上做一个线性滤波（卷积）对应的单位ary/CP map（这会引入跨 bin 的 MPO 或者把 bins 做 FFT 再乘 transfer function）。
- 如果你要“指导实验窗口选择/匹配滤波器带宽”，色散/PMD 是很难绕开的。

------

### 4.4 探测：bucket + 暗计数是够用的，但缺少 “探测器时间抖动/死时间/后脉冲”

你现在的探测 POVM 结构是合理的：6D 端口空间 + bucket detector + η_det + dark splitting，枚举/抽样也自洽

但实验上对符合窗口、binning 的系统误差通常来自：

- timing jitter：点击时间会在 bin 上扩散（等效把 click POVM 在相邻 bin 做卷积）
- dead time：短时间内多次点击被吞掉 → 改变多光子/噪声事件的统计
- afterpulsing：暗计数不是泊松独立

你现在把所有噪声都变成 per-bin 独立概率 `p_noise`
这对“平均成功率”可能够，但对“点击记录分布随窗口变化”可能会失真，从而影响你用仿真去指导实验分析窗的能力。

## 6) 你还“缺的东西”（如果目标是强实验指导意义）

下面是我认为最值得补的“最小集合”（按投入产出比）：

1. **把 QFC 转换效率（θ_H/θ_V）参数化 + 可扫描**

   这是你想解释 fidelity 下降机理的核心诊断量。
3. **加入“可调的干涉可见度/模式失配”参数 V（等效）**
   即使你用 MPS 得到了波包，也仍会有实验里的空间模式不匹配、频谱滤波差异等不可见自由度。一个简单有效的实验对齐做法是引入一个参数 V，把 BS 干涉分成“可干涉部分 V”和“不可干涉部分 1−V”。

4. **修复并输出 “dark vs no-dark” 两套枚举指标**（见 2.1）
   否则你很难把“暗计数污染”与“系统误差污染”区分开。
5. （如果你真要指导窗口选择）**加入 timing jitter 的 bin 卷积模型**
   这是把“符合窗-误判率-保真度”连接起来的关键。
