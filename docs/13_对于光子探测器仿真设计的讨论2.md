## 1) 为什么“每 bin 独立点一下”会出错

你担心的两类怪现象：

- “同一 bin 下四个探测器都响”
- “不同 bin 下先 H1、V1 响完了后面 H2 还响”

在“真实两光子态 + 无暗计数”的理想情况下，**这些事件的 Born 概率应当严格为 0**。之所以你会担心它们出现，通常是因为你在做类似这样的事情：

- 先算每个 bin 的边缘概率（比如 ⟨n̂⟩ 或者局域 density）
- 然后对每个探测器/每个 bin 独立抽样

这等价于把联合分布近似成了边缘分布的乘积，直接破坏了**相干项**和**“测量导致塌缩”**带来的条件概率更新。

正确做法是：**每发生一次测量结果，就用对应的测量算符把全态更新（塌缩）**，再去算后面 bin 的概率。你的讨论稿里也强调了这一点：两光子问题的自然框架就是量子跳跃/量子轨迹。

## 2) 你要的“点击算法”最干净的表述：Kraus/Jump 递推

把 BS 后的输出模式标成 4 个探测器：

- port 1 的 H/V → H1, V1
- port 2 的 H/V → H2, V2

每个时间 bin 是一组正交模式，所以“按时间推进”就是对 bin 逐个做测量。

### 2.1 一条轨迹的测量概率（Born 规则）

设你在第 n 个 bin 做一次测量，测量结果 μ 是 16 种点击模式之一：

[
\mu \in {(d_{H1},d_{V1},d_{H2},d_{V2})},\quad d\in{0,1}
]

对应一个只作用在该 bin 的测量算符（Kraus）(K_{\mu}^{(n)})。
那么在“当前条件态” (|\Psi\rangle) 下，结果 μ 的概率就是：

[
p_{\mu}(n)=|K_{\mu}^{(n)}|\Psi\rangle|^2
]

抽到 μ 之后，更新态：

[
|\Psi\rangle \leftarrow \frac{K_{\mu}^{(n)}|\Psi\rangle}{\sqrt{p_\mu(n)}}
]

**这一步就是你要的“点击会影响后面所有 bin 的条件概率”。**
因为你后面再算 (p_{\nu}(m))（m>n）的时候用的是更新后的 (|\Psi\rangle)。

你的 MPS 容器已经提供了“按 Kraus 抽样并归一化更新”的接口：`apply_kraus_one_site / apply_kraus_two_site`。

## 3) 两种实现方式：你选哪个都行

### 方案 A（最推荐）：**逐 bin 16-outcome Kraus 扫描**

这最接近你说的“探测器视角：bin 依次进入探测器”。

**流程：**

对 n = N → 1（按你定义的时间顺序）：

1. 取出这个 bin 的两个输出端口（两个 MPS site：port1、port2）
2. 对这两个 site 一起做一次“16 结果测量”（H1,V1,H2,V2 四个 on/off）
3. 抽样得到 μ=(dH1,dV1,dH2,dV2)
4. 立刻用对应 Kraus 更新 MPS（塌缩）
5. 记录点击
6. 这个 bin 以后不会再参与任何演化/测量了：把它“冻结/切断”以保证复杂度线性（你已经在 `finalize_bin_pair` 里实现了这个思路）

你在 `TrajectoryRunner.run_bin()` 里其实已经按这个结构写好了：
(5) BS 两格点酉门 → (6) 两格点探测 Kraus → (7) finalize_bin_pair。

> 这个方案的关键优点：
> **你不用手写“禁止乱点”的规则**。
> 哪个模式不可能，那个 μ 的 Born 概率就是 0，自然抽不到。

------

### 方案 B：**事件驱动（只找第一次点击、再找第二次点击）**

这就是你讨论稿里“方法B 的两光子升级版”。

它更像你脑海里“探测器在等第一次 click”的感觉，通常也更省事（因为两光子最多两次 click，你可以两次之后直接停）。

**第一跳：**在还没发生任何点击的条件下，从早到晚扫 bin：
[
p_\alpha(n)=\langle \Psi^{(0)}|J^\dagger_{\alpha,n}J_{\alpha,n}|\Psi^{(0)}\rangle
]
[
p_{\text{any}}(n)=\sum_{\alpha\in{H1,V1,H2,V2}}p_\alpha(n)
]
抽到第一次点击 (α,n)，态更新为：
[
|\Psi^{(1)}\rangle=\frac{J_{\alpha,n}|\Psi^{(0)}\rangle}{\sqrt{p_\alpha(n)}}
]

**第二跳：**在 (|\Psi^{(1)}\rangle) 上继续扫，抽到 (β,m)，再 jump 一次。

这个方案特别适合你在 `total_simulation.py` 里做的那种“先把 MPS 归一化到双光子分支，再只关心两次点击”工作流（你代码里就写了 `run_two_photon_detection` 是“物理正确”的新方法）。

## 4) 你最关心的点：怎么保证“不乱点”以及“点击后更新条件概率”？

只要你用上面任一方案（A 或 B），下面这些都会自动成立：

### 4.1 “同一 bin 四个探测器都响”不会发生

因为你的系统里总光子数最多 2（双原子各发一个），BS 也守恒光子数。
四个探测器都响意味着至少 4 个光子，Born 概率为 0，所以抽不到。

如果你曾经看到这种结果，几乎可以断定你用的是“边缘概率独立抽样”而不是“Kraus 塌缩抽样”。

### 4.2 “先 H1、V1 响完后面 H2 还响”不会发生（无暗计数前提下）

这等价于 3 次点击，仍然需要 ≥3 光子，所以概率为 0。
用 Kraus/Jump 更新后，态里可被探测的光子数会被测量逐步“吃掉/投影掉”，后续不可能再凭空出一个第三次 click。

### 4.3 “探测器先触发会影响后面 bin 的概率”如何体现？

这句话用量子测量语言翻译就是：

> 后面的概率不是用原态 (|\Psi\rangle) 算，而是用条件态 (|\Psi \mid \text{已发生点击}\rangle) 算。

而这恰恰就是 Kraus 更新：

- 你抽到 μ 后，马上令
  (|\Psi\rangle \leftarrow K_\mu|\Psi\rangle/\sqrt{p_\mu})
- 后面 bin 的任何概率，都是在新 (|\Psi\rangle) 上算的

所以你不需要额外写“抹除其它探测器组合”的人工规则；**塌缩本身就是那个“抹除”。**

## 5) 结合你当前的局域基：怎么构造“探测 Kraus”（bucket SNSPD）

你给单臂单 bin 的光子子空间是：
`vac, H, V, 2H, 2V, HV`（这正是你代码里 `SUBSPACE_1517` 的 6 维基）

把每个基态映射成 (n_H,n_V)：

| basis | n_H  | n_V  |
| ----- | ---- | ---- |
| vac   | 0    | 0    |
| H     | 1    | 0    |
| V     | 0    | 1    |
| 2H    | 2    | 0    |
| 2V    | 0    | 2    |
| HV    | 1    | 1    |

### 5.1 bucket(on/off) + 探测效率 η（忽略暗计数时）

对一个“单个探测器”来说（比如 H 通道）：

- no-click 概率：((1-\eta)^{n_H})
- click 概率：(1-(1-\eta)^{n_H})

对同一端口的 H/V 两个探测器独立（这是 PBS 后两个独立 SNSPD 的常规模型）：

[
P(d_H,d_V \mid n_H,n_V)
= P_H(d_H\mid n_H),P_V(d_V\mid n_V)
]

于是一个端口（一个 site）有 4 个结果：00/10/01/11。

### 5.2 变成 Kraus（用于 MPS 的 `apply_kraus_*`）

最工程化的做法是：让 Kraus 在这 6 维基上是**对角**的：

[
K_{d_H d_V}=\mathrm{diag}\Big(\sqrt{P(d_H,d_V\mid \text{basis}*j)}\Big)*{j=0..5}
]

- 它满足 (\sum_{d_H,d_V}K^\dagger K = I)（因为每个 basis 上概率和为 1）
- 抽到某个结果后，你用 `apply_kraus_one_site` 归一化更新，就实现了条件塌缩

然后两个输出端口（port1、port2）合起来就是 16 个结果，Kraus 可以取张量积：

[
K_{\mu}^{(n)} = K^{(1)}*{d*{H1}d_{V1}}\otimes K^{(2)}*{d*{H2}d_{V2}}
]

你可以：

- **一次性做 16-outcome 两格点 Kraus**（用 `apply_kraus_two_site`）
  ——这对应我上面“方案A”的实现方式。
- 或者 **先测 port1 再测 port2**（两次 `apply_kraus_one_site`）
  ——只要中间更新态，等价于联合抽样（因为是产品 POVM）。

你在旧 `apply_detection()` 里用的就是“一格点 POVM × 2 site”的写法（只是注意你现在新链结构里，bin 的索引要跟 `apply_bs()` 一致：atomA,atomB 在 0,1，bin 从 2 开始）。

## 6) 你说的“一个探测器不能 click 两下”怎么加进去？

这其实是“探测器有死时间/饱和”的经典限制。实现时建议把它当成 **探测器的经典状态机**，叠加在量子 Kraus 抽样之上：

- 维护 `armed[H1], armed[V1], armed[H2], armed[V2]`（或 next_available_bin）
- 如果某个探测器已经点过且还没恢复，那么后续 bin：
  - 该探测器的 click 结果强制为 0（不再记录）
  - 但 arriving 的光子仍然“被吸收但不产生计数”（在量子上相当于效率置 0 的吸收通道）

在只考虑“两光子、且只关心 coincidence(BSM)”的场景里，这个细节通常不会影响你要的成功事件（因为成功事件需要两个不同探测器/端口的点击，天然不会让同一个探测器连点两次）。

## 1) `get_reduced_density([site_A, site_B])` 是合法的吗？代表什么？

`MPSState.get_reduced_density(sites)` 调的是真正的 TeNPy `get_rho_segment()`，它做的是**对除了 sites 之外的所有自由度做偏迹**，得到 sites 的约化密度矩阵。

所以：

- 这一步在数学上**是完全正确、有明确物理含义**的：
  你得到的是“只看两个原子时，它们处于什么混态”。

它不关心你有没有做 BSM，它只反映“当前全局态”下原子与其它系统（所有光子bin）纠缠后，原子本身呈现的混合程度。

## 2) `extract_spin_state()` 实际做了什么？（以及它引入的“额外后验条件”）

`extract_spin_state(mps, n_bins)` 的流程是：

1. 取两原子的约化态 `rho_full = mps.get_reduced_density([0,1])`（9×9）。
2. 只取其中对应 **|0/1⟩ ⊗ |0/1⟩** 的 4×4 子块：
   `qubit_indices = [0,1,3,4]`。
3. **把这个 4×4 子块再除以它自己的迹**（`rho_qubit /= Tr(rho_qubit)`）。

第 3 步非常关键：
这等价于你又做了一次经典意义上的**后选**：

> “只统计/只关心两个原子最终都落在 {|0⟩,|1⟩} 这个量子比特子空间里的那部分分支”。

如果原子还有残留的 |e⟩ 占据（或者泄漏到其它子空间），那么 `Tr(rho_qubit)<1`，你这里的归一化会把那部分概率直接丢掉。
所以 `extract_spin_state()` 返回的 4×4 密度矩阵在解释上是：

- **(后选1)**：先对光子所有 bin 偏迹（因为你只取原子）
- **(后选2)**：再条件化在“原子都在 qubit 子空间”这一事件上（因为你把 4×4 子块归一化了）

这不是“错误”，但它确实是**额外的后验条件**，会让你算出来的 Bell fidelity 变得更“乐观”（因为把 |e⟩ 泄漏那部分丢了）。

建议你至少同时输出一个数：
`p_qubit = Tr(rho_qubit_before_norm)`，这样你知道自己到底丢了多少概率。

## 3) 那么它到底是“后验纠缠程度”还是“没意义的数”？

### 情况 A：你把 **测量前** 的 MPS 喂给 `extract_spin_state()`

这时它给出的东西是：

这当然是有意义的量：它告诉你在**还没做探测**时，原子自身已经有多少纠缠/相干（通常会因为与光子纠缠而呈混态）。

这就是典型的**heralded entanglement 的后验指标**。不是“没意义的数”。

## 1) “要求同 bin”到底等价于什么？为什么会随 dt→0 变成 0 概率？

如果你把时间分辨率设为 dt，并且你规定：

> “两个 click 必须发生在同一个 bin 才算 coincidence”

对任意连续分布来说，当 dt→0，(|t_1-t_2|<dt) 的概率都会线性缩到 0（因为你把接受窗口压到 0 宽度了）。

所以你的担心是对的：**“同 bin”判据本质上是在把 coincidence window 设成 dt**。dt 越小，窗口越小，概率越小。

但注意：这不是物理定律要求的，而是你自己选了一个随 dt 变化的“判据”。

------

## 2) 实验里真正的 coincidence 不是“同一时刻”，而是“有限时间窗 W”

真实实验里，BSM 的“同时”永远不是数学意义的同时，而是：

- 电子学的 coincidence 窗口 (W)（比如几百 ps 到几 ns，视 SNSPD jitter/电子学而定）
- 或者你人为设置的后处理窗口（gating / time filtering）

**关键：(W) 是一个物理时间尺度，与你仿真的 dt 无关。**

所以在 time‑bin 仿真里应该这样做：

- 你可以把 dt 取得很细，用来逼近连续波包、计算干涉更准；
- 但是你判定“coincidence”的窗口要固定为物理 (W)：
  [
  |t_1-t_2|\le W
  \quad\Leftrightarrow\quad
  |n_1-n_2|\le K,;;K=\left\lceil \frac{W}{dt}\right\rceil
  ]
- 当 dt 变小，(K) 会变大，**从而保持同一个物理窗口 (W)**，这样成功概率不会“因为你细分了 bin”而消失。

## 3) 更重要的一点：BSM 成功并不需要“同 bin”，很多情况下 (n_1\neq n_2) 也完全物理

你现在的 `check_bsm_success(clicks)` 确实只看探测器集合 `{H1,V2}` 等，不看两个 click 的 `bin_index`。
你担心这“太松”，我之前提醒你“可能会错”，但现在结合你提出的这个疑问，我们要把话说得更精确：

### 3.1 两个 click 落在不同 bin 是正常的、甚至是主要贡献

如果光子波包跨很多 bin，那么两个光子各自的到达/被探测时间就是随机的。即使两光子完全同步、完全不可区分，它们的两次 click 也不需要发生在同一个 dt 宽度里。

### 3.2 什么时候“不同 bin 仍然是好 BSM”？

这取决于：**检测记录里“时间信息”有没有给你提供 which‑path / distinguishability 信息**。

一个非常典型的结果是：如果两边光子的时域波包完全相同（(\psi_A(t)=\psi_B(t))），那么很多成功模式下，**后验原子态会因子分解成“时间因子 × 固定 Bell 态”**，这意味着：

- 你不需要强迫 (n_1=n_2)；
- 你甚至可以不关心 (n_1,n_2)（只关心“哪两个探测器响”），后验原子态仍然接近某个 Bell 态；
- 这时候 `check_bsm_success` 忽略 bin 反而是合理近似。

### 3.3 什么时候“不同 bin 会降低纠缠/保真度”？

当两边光子波包不匹配时（比如你自己提到的 ΔT、形状差异、频谱差异、相位噪声等），那么同一对探测器（比如 H1+V2）在不同的 ((n_1,n_2)) 上，会对应不同的后验原子态。

如果你：

- 记录了 ((n_1,n_2)) 并对每次事件分别算后验态 → 你会看到后验态随时间标签变化；
- 但你在实验/仿真里“宣告成功”时不利用这个时间信息（相当于把时间标签丢掉） → 你得到的是这些后验态的**混合**，保真度会下降。

这不是“bin 越细越糟”，而是**你是否在后处理里丢掉了可区分信息**。

## 5) 那保真度到底怎么定义才不“随 dt 变化出怪事”？

这里有两种你可以明确区分的“物理上都合理”的保真度定义：

### A) **time‑tagged（有时间戳）后验保真度**

你每次成功事件都有一个完整记录：((\alpha,n_1),(\beta,n_2))。

- 或者允许做基于 ((n_1,n_2)) 的 feed‑forward（比如相位补偿）再算 fidelity。

这个定义下，dt 变小不会让“概念”崩溃，因为你始终在条件化在**具体的测量记录**上。

### B) **coarse‑grained（丢时间戳）成功事件的保真度**

这更像很多实验最终报告的：

> “只要在窗口 W 内，探测器组合属于 {H1,V2} 或 {V1,H2}，就算成功；不再区分具体时间差。”

这在量子测量语言里等价于：你把很多不同的 Kraus 分支（不同 bin 的成功事件）**做经典混合**。
那最终原子态一般是混态，保真度会下降，这就是“时间可区分性导致的退相干”。

这个定义下：

- dt 越小只是把积分做得更精细；
- 真正控制 fidelity / success rate 权衡的是 **窗口 W**（以及两光子波包匹配程度），不是 dt。

   如果某些 bin 的占据概率小但不为零，而你阈值设得偏大，它们就永远不会被测到——那你得到的 click 时间分布、成功率、后验原子态都会被偏置。
2. **条件态不自洽**
   第一次 click 会改变第二个光子的条件分布（这是你最初在理论上强调的“测量引入条件概率更新”）。
   但你这里的 bins 筛选是基于**测量前的边缘期望**做的，之后不更新，这在有强时间相关（比如 ΔT、或两光子相关结构）时可能会漏掉“测量后才变重要”的 bin。

所以：即使你“break”本身未必错，**“只测部分 bins”**这件事本身就已经让它不再是严格的“逐 bin 探测仿真”。

------

### (B) 更直接的 bug：注释说“投影未探测 bins 到 |vac⟩”，但代码根本没做

你这里写了注释：

> “提取探测后的原子态（投影所有未探测的bins到|vac>）”

但实际 `extract_spin_state_after_detection` 只是直接调用 `extract_spin_state`，也就是**对所有 bins 做 trace**，并没有把未测 bins 投影到 vacuum。

这意味着：

- **如果**早停时剩余 bins 不是严格 vacuum（例如以后你加入暗计数、>2 光子、或桶式探测器导致“两光子进同一探测器只记一次 click”等），
- 那么你现在算出来的 `spin_state` 就是“把那些未测 bins 当成环境直接丢弃”的结果，**不等价于**“条件在‘未测 bins 都没有 click’/‘未测 bins 都是 vacuum’”的后验态。

换句话说：
`break` + “未测 bin 不处理” + “只做 trace”
会把你想要的 **heralded / 后验态** 变成一个 **粗粒化（coarse-grained）混态**。

## 3) 怎么判断你现在这条 `break` 到底有没有在“成功分支”上造成问题？

最简单的自洽检查就是：
在 `break` 后（两次 click 之后）算一下**剩余 bins 的总光子数期望**是不是≈0。

你已经有现成的统计函数：`compute_photon_statistics(mps, n_bins)` 会把所有 bins 的 ⟨n⟩加起来。

如果在成功事件里它仍明显大于 0（比如 >1e-3 甚至 >1e-2），那就说明你早停时场里还有残留光子/残留纠缠——那你的担心就真的是“真问题”。
