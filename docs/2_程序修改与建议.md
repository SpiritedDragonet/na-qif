## 2) TeNPy 中“局域 TEBD 更新内核”的推荐写法（支持 Unitary 和 Kraus）

你要的核心是：

- 只在 bond `(i,i+1)` 上做局域更新
- 不调用 `canonical_form()`
- 每次更新结束后 MPS 仍保持 canonical（或至少保持 TeNPy 可继续调用 `get_theta`）

TeNPy 给了两块关键积木：

- `get_theta(i, n=2)`：取出两站点波函数 `theta`（腿标签一般是 `vL, p0, p1, vR`） ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))
- `set_svd_theta(i, theta, trunc_par=...)`：把“已准备好做 SVD 的两站点 theta”做 SVD 写回 MPS（并可截断） ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))

注意：`set_svd_theta` 的文档明确要求 `theta` 的腿标签要先合并成 `"(vL.p0)"` 和 `"(p1.vR)"`（也就是两条腿的矩阵形式）再 SVD。 ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))
这一步在 TeNPy 里就是 `theta.combine_legs(...)`。

下面我给你一个“你可以直接塞进 wrapper 的最小内核”。

------

### 2.1 通用：施加任意两站点算子（幺正或非幺正）并做局域 SVD 写回

思路：

1. `theta = psi.get_theta(i, n=2)` 得到 `vL,p0,p1,vR`
2. 用 `npc.tensordot` 或 numpy 把算子 contraction 到 `p0,p1` 上
3. 把腿顺序整理回 `vL,p0,p1,vR`
4. `combine_legs([['vL','p0'],['p1','vR']])`，得到两条腿
5. `psi.set_svd_theta(i, theta, trunc_par=...)` 写回

关键点是 **算子腿标签**要用 `apply_local_op` 同样的规则：`['p0','p1','p0*','p1*']`。TeNPy 文档说明 `apply_local_op` 就是靠这些 label 推断作用的站点数、以及哪条腿收缩哪条腿。 ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))
我们这里虽然不用 `apply_local_op`，但沿用同样的 label 习惯会让你少踩坑。

你可以实现一个函数：

- 输入：`gate_4d`（形状 `(d0,d1,d0,d1)`，对应 out,out,in,in）
- 输出：更新后的 MPS

并且每次都用 `trunc_par` 控 chi_max。

------

### 2.2 Kraus 抽样：两站点量子信道的一次轨迹更新（“选一个 Kraus 分支”）

你要做的是：

给定一组 Kraus `{K_μ}`（同样是两站点算子），对当前两站点局域波函数 `θ`：

- 计算每个分支的概率
  (p_\mu = |K_\mu \theta|^2)
- 按 (p_\mu) 抽样出一个 μ
- 取 `θ' = K_μ θ / sqrt(p_μ)`（归一化）
- `set_svd_theta` 写回

这个过程完全局域，不需要全链 canonical sweep。并且它和实验“环境被测到某个结果”在物理上是对应的（量子轨迹）。

------

### 2.3 你最关心的性能点：为什么这不会像 `canonical_form()` 那样炸

- `canonical_form()` 是 **全链 sweep**：基本就是对每个 bond 都来一次分解和更新
- 而 `set_svd_theta(i, ...)` 只更新 **一个 bond** 的两站点张量

所以复杂度从 “每次 Kraus O(L)” 变成 “每次 Kraus O(1)（只跟局域 χ、d 有关）”。

## 2) TeNPy 中“局域 TEBD 更新内核”的推荐写法（支持 Unitary 和 Kraus）

你要的核心是：

- 只在 bond `(i,i+1)` 上做局域更新
- 不调用 `canonical_form()`
- 每次更新结束后 MPS 仍保持 canonical（或至少保持 TeNPy 可继续调用 `get_theta`）

TeNPy 给了两块关键积木：

- `get_theta(i, n=2)`：取出两站点波函数 `theta`（腿标签一般是 `vL, p0, p1, vR`） ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))
- `set_svd_theta(i, theta, trunc_par=...)`：把“已准备好做 SVD 的两站点 theta”做 SVD 写回 MPS（并可截断） ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))

注意：`set_svd_theta` 的文档明确要求 `theta` 的腿标签要先合并成 `"(vL.p0)"` 和 `"(p1.vR)"`（也就是两条腿的矩阵形式）再 SVD。 ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))
这一步在 TeNPy 里就是 `theta.combine_legs(...)`。

下面我给你一个“你可以直接塞进 wrapper 的最小内核”。

------

### 2.1 通用：施加任意两站点算子（幺正或非幺正）并做局域 SVD 写回

思路：

1. `theta = psi.get_theta(i, n=2)` 得到 `vL,p0,p1,vR`
2. 用 `npc.tensordot` 或 numpy 把算子 contraction 到 `p0,p1` 上
3. 把腿顺序整理回 `vL,p0,p1,vR`
4. `combine_legs([['vL','p0'],['p1','vR']])`，得到两条腿
5. `psi.set_svd_theta(i, theta, trunc_par=...)` 写回

关键点是 **算子腿标签**要用 `apply_local_op` 同样的规则：`['p0','p1','p0*','p1*']`。TeNPy 文档说明 `apply_local_op` 就是靠这些 label 推断作用的站点数、以及哪条腿收缩哪条腿。 ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))
我们这里虽然不用 `apply_local_op`，但沿用同样的 label 习惯会让你少踩坑。

你可以实现一个函数：

- 输入：`gate_4d`（形状 `(d0,d1,d0,d1)`，对应 out,out,in,in）
- 输出：更新后的 MPS

并且每次都用 `trunc_par` 控 chi_max。

------

### 2.2 Kraus 抽样：两站点量子信道的一次轨迹更新（“选一个 Kraus 分支”）

你要做的是：

给定一组 Kraus `{K_μ}`（同样是两站点算子），对当前两站点局域波函数 `θ`：

- 计算每个分支的概率
  (p_\mu = |K_\mu \theta|^2)
- 按 (p_\mu) 抽样出一个 μ
- 取 `θ' = K_μ θ / sqrt(p_μ)`（归一化）
- `set_svd_theta` 写回

这个过程完全局域，不需要全链 canonical sweep。并且它和实验“环境被测到某个结果”在物理上是对应的（量子轨迹）。

------

### 2.3 你最关心的性能点：为什么这不会像 `canonical_form()` 那样炸

- `canonical_form()` 是 **全链 sweep**：基本就是对每个 bond 都来一次分解和更新
- 而 `set_svd_theta(i, ...)` 只更新 **一个 bond** 的两站点张量

所以复杂度从 “每次 Kraus O(L)” 变成 “每次 Kraus O(1)（只跟局域 χ、d 有关）”。

------

## 3) 把它落到你这份 wrapper：你该怎么改

你目前的核心接口是：

```python
def apply_two_site_gate(self, site_left, gate):
    op_arr = Array.from_ndarray_trivial(... labels=['p0','p1','p0*','p1*'])
    self._mps.apply_local_op(site_left, op_arr, unitary=True)
```

建议改成两层：

### 3.1 底层：`_apply_two_site_op_local(i, op_arr, trunc_par, normalize=False)`

- 不再用 `apply_local_op`
- 用 `get_theta` + contraction + `combine_legs` + `set_svd_theta`
- `normalize=True` 用于 Kraus 归一化之后的写回（一般你提前就归一化了）

这里你要用到：

- `get_theta(i, n=2)` ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))
- `set_svd_theta(i, ...)` ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))

### 3.2 上层：`apply_two_site_gate_unitary(i, U)`

- 直接调用底层 local update
- 仍旧可以支持 truncation

### 3.3 上层：`apply_two_site_kraus(i, [K0,K1,...], rng)`

- 先用底层生成每个 `Kμ θ` 的临时 `theta_mu`
- 算 `pμ`
- 抽样
- 归一化并写回

## 4) 什么时候 purification 比 Kraus 更合适？以及你当前为什么 Kraus 仍然是主线

你现在的任务是“链路 + heralded（双光子符合）”这类协议，本质上你会反复问：

- 成功率是多少（双击概率）？
- 条件成功时，原子对的保真度/纠缠度是多少？
- 噪声来自哪些环节（损耗、偏振漂移、暗计数、频转噪声、原子退相干）？

对这种 **条件化/后选择** 的流程：

- **Kraus/量子轨迹**天然契合：一次 trial 对应实验一次运行；你抽样“是否丢光子/是否探测点击/是否暗计数”等随机事件，然后统计。
- purification 更像“把密度矩阵整体推进”，它适合做无条件演化（比如热态、Lindblad 的确定性演化），但一旦你引入“符合探测宣告成功并投影”的逻辑，你依然要在密度矩阵上做条件化更新，而且算力更重（局域维度相当于翻倍的物理腿，bond 也更容易涨）。PurificationMPS 的定义本身就是“每个站点多一个 ancilla 物理腿 q”。 ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.purification_mps.PurificationMPS.html?utm_source=chatgpt.com))

所以你现在坚持 Kraus 作为主线是合理的；关键是**实现方式要局域化**，不要触发全链 canonicalization。

## 5) 我给你一个“最小正确性检查清单”（强烈建议你边改边做）

你现在最容易出现的 bug 是：“能跑，数据也像那么回事，但实际上门或 Kraus 的 index 顺序错了”。

为了确保你“门的 reshape、腿的顺序、抽样概率”的一切都对，我建议你做如下验证（都可以在 L≤6 的小系统用 dense matrix 做对照）：

1. **两站点幺正门**：对随机 MPS（或 product state）施加 U，用你的 local update vs dense 对照，误差 < 1e-10。
2. **单次 Kraus 信道**：给一组 Kraus，
   - 验证 (\sum_\mu p_\mu = 1)（数值误差范围内）
   - 抽样很多次后，分支频率 ~ pμ
3. **规范形式 sanity**：每一步之后跑 `psi.test_sanity()`（TeNPy 有这个方法）确保 canonical 没坏掉。 ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))
4. **局域密度矩阵**：用 `get_rho_segment([i])` 和你自己 contraction 的版本对照一致。 ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))

## 6) 回答你最核心的那个问题：TeNPy 中走 Kraus 代价高吗？

结论非常明确：

- **“Kraus 本身”不高**；
- **“用 `apply_local_op` 做非幺正 Kraus”很高**，因为它会触发 `canonical_form()` sweep。 ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))
- 改成 `get_theta + set_svd_theta` 的局域更新后，Kraus 的代价和普通 TEBD 两站点门同一个量级（都是“一次局域 SVD + 截断”）。 ([TeNPy](https://tenpy.readthedocs.io/en/stable/reference/tenpy.networks.mps.MPS.html))

所以你的路线是：

> Kraus/轨迹法不变
> ⟶ 关键实现从 `apply_local_op(non-unitary)` 改成 “局域 theta 更新 + 局域 SVD 写回”
> ⟶ 性能问题基本解决
