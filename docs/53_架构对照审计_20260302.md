## 2. 当前唯一主路径（代码事实）

### 2.1 调度与任务协议（入口）

- 入口是 `total_simulation.py`，协议版本 `v2_core_trial`，任务模式分 `CORE_TRIAL` 与 `SUMMARY`。
- `CORE_TASK_BUILDERS` 与 `CORE_TRIAL_TASK_RUNNERS` 已把 `SIM/HOM/PARAM_SCAN/WINDOW_SCAN/BSM_SCAN/LENGTH_SCAN/QFC_NOISE_SCAN/QFC_EFF_NOISE_SCAN/DETECTOR_BG_SCAN` 统一接入。
- server 先写 `run_manifest.json`，再建核心任务；worker 执行核心任务后执行汇总任务。

结论：任务协议主路径单一且闭环，不存在“旧模式并行运行”的主流程分叉。

### 2.2 单次物理链路

统一入口是 `atom_sim/experiment/common.py::run_emission_to_bs`：
1. `run_dual_atom_emission`（态端发射）
2. `apply_qfc_filter_memory_chain`（态端 QFC+滤波记忆）
3. `sample_fiber_realization`（采样光纤参数）
4. 原子退相干
5. BS 不在态端显式作用，进入测量端 effect

探测端在 `atom_sim/simulation/detection.py::run_detection_pipeline`：
- 先算到达统计 `p_arrive/p_arrive_11/p_arrive_same_arm`
- 再构造逐 bin 5D effects（含 `v_res` 混合、光纤参数、探测参数）
- 枚举成功概率、真假成功分量、Bell 条件态、CHSH
- 可选抽样生成点击记录

结论：`readme.md` 所述“态端发射+QFC记忆，BS并入测量端”与实现一致。

### 2.3 指标与输出链路

- 单任务指标在 `single_run.py` 汇总为 `success_metrics`。
- 全局 CSV 汇总在 `summary.py::write_summary` 分 task 写出 `*_trials.csv / *_runs.csv / *_summary.csv`。
- WINDOW_SCAN、LENGTH_SCAN、BSM_SCAN、QFC_EFF_NOISE_SCAN、DETECTOR_BG_SCAN 的汇总字段命名已对齐图脚本读取口径（见第 4 节）。

## 4. 图脚本与数据接口审计

### 4.1 已对齐（可复现）

1. `fig_window_tradeoff.py`
- 支持从 `window_scan_summary.csv` 读取现代字段（如 `herald_rate_abs`, `p_success_true_abs_avg`, `false_fraction_global`），并有旧字段兼容映射。

2. `fig_distance.py`, `fig_chsh.py`
- 读取 `length_scan_summary.csv` 的 `p_success_true_abs_avg/fidelity_true_avg/chsh_s_max_avg` 等字段，与 `summary.py` 产出一致。

3. `fig_qfc_noise.py`, `fig_detector_eff.py`
- 分别读取 `qfc_eff_noise_scan_summary.csv` 与 `detector_bg_scan_summary.csv`，字段口径与 `summary.py` 一致。

4. `fig_hom.py`
- 读取 `hom_summary.csv`，并支持聚合格式。

### 4.2 风险点（图层）

1. 多脚本默认路径硬编码到历史 run 目录
- 例如 `fig_window_tradeoff.py`, `fig_accept_hist.py` 默认指向特定历史输出目录。
- 这不会破坏主流程，但会导致“新机器/新 run 直接运行失败或读到旧数据”。

2. `fig_bell_density_3d.py` 默认读 `thesis/data/.../declared_density_matrix.json`
- 该文件不是常规 summary 自动产物；需要确保运行链路额外导出该 JSON。

## 6. 风险清单（按严重度）

### P0（立即影响论文交付可信度）

1. 模板占位文本被编译路径启用
- `back/publications.tex`, `back/resume.tex`, `back/acknowledgements.tex`, `front/cover.tex`。

### P1（影响复现与协作效率）

1. 图脚本默认输入目录绑定历史 run
- 跨环境复现需要手工改参数或目录。

2. Bell 密度矩阵图依赖非标准产物
- 若缺少 `declared_density_matrix.json`，图脚本会中断。

3. docs 重复与状态混杂
- 新成员容易把已过时建议误当现行规范。

### P2（技术债，短期可接受）

1. 入口与汇总文件偏大
- `total_simulation.py`, `summary.py`, `single_run.py` 长度较高，维护成本上升。
- 目前结构仍可运行，未见阻断性错误。

## 7. 编辑前安全边界（给后续改动用）

### 可直接改（低风险）

1. 论文 front/back 非研究内容清理（占位替换、无关模板段删除）
2. 图脚本默认路径参数化（不改计算逻辑）
3. docs 去重与索引化（不改代码行为）

### 需先锁口径再改（中高风险）

1. `summary.py` 字段重命名或删列（会连锁影响 `thesis/figures/*.py`）
2. `single_run.py` 指标口径调整（会改变论文图数值）
3. `detection.py` 成功判据和分解逻辑（影响 `p_success_*`, `fidelity_*`, `chsh_*`）
