# 1) 必须立刻修的硬错误：`v_res` 的“可区分光子模型”构造是错的

## 1.1 你现在的实现方式（问题点）

在 `build_detection_effects_5d_by_bin()` 里，如果 `v_res < 1`，你会：

1. 构造 9D（带标签）探测 POVM
2. 通过 `embed_9_from_6()` / `reduce_9d_effects_to_6d()` 把 9D effect **投影回 6D**
3. 再用 `mix_effects(..., v_res)` 在 6D 层做凸组合
4. 最后投影到 3D 单光子输入空间（`project_6d_to_3d`）

关键问题在于：

- `embed_9_from_6()` 的定义是把 6D 的 |H>,|V> 映射为 **(a+b)/√2 的对称态**（也就是 boson 对称化的 embedding）
- 但“可区分光子”模型在输入端的物理含义是：
  **A 臂的光子是 label-a，B 臂的光子是 label-b**（来源标签与空间臂绑定）
  而不是 `(a+b)/√2` 的对称叠加。

因此你现在做的 `reduce_9d_effects_to_6d` 相当于用“错误的嵌入”去回投影，导致：

- 在 `v_res=0`（完全可区分）极限下，POVM 在输入 3D×3D 子空间上**不再完备**
- 典型的 HOM 经典结果（两光子 |H,H> 入射 50/50 BS，输出 coincidence 50%）会被你算成 0（我用你代码现有实现验证过）。

> 你在 `run_detection_self_checks()` 里做的自检并没有发现这个问题，因为自检只验证了你“自己的回投影逻辑”在内部一致（即 v_res=0 就等于你构造的 reduced_dist），但没有验证 reduced_dist 是否等价于物理上正确的“可区分极限”。

## 1) 先回答你关心的物理事实：780 在这条链路上基本就是“必然丢掉”

### 光纤本身并不是“只让 1517 过”的理想带通

石英光纤不是一条窄带滤波器，它在可见到近红外都有传输窗口；但**损耗随波长变短会显著上升**，主要原因之一是 Rayleigh 散射大致按 ( \lambda^{-4} ) 增强。([MSU Web Physics](https://web.pa.msu.edu/courses/2011fall/PHY431/Labs/QuantumOptics/Components/Optics/Fiber Optics/Fiber Optic Basics.pdf))

对“780 nm 能不能在光纤里传 16 km”这个问题：
即便用**专门支持 780–970 nm 的单模光纤**，Thorlabs 给的最大衰减也到 **≤ 4.0 dB/km @ 780 nm**。([Thorlabs](https://www.thorlabs.com/single-mode-fiber))
那 16 km 就是 **≥ 64 dB** 的额外损耗量级（透过率 (\sim 10^{-6.4}\approx 4\times 10^{-7})），还没算连接器/熔接/器件的额外抑制。也就是说，从“链路透过率”角度，它确实可以视作**极小量**。

更贴近你实验的情况是：你用的是**电信链路光纤**（例如 SMF-28 类）来跑 1517 nm。对这种“设计工作在 1.3/1.55 µm 的单模光纤”，在**低于截止波长**使用时会开始呈现多模特性、模式不稳定等问题；工程文档通常会明确说“短于 cutoff 就不再单模，会像多模那样工作”。([OZ Optics](https://www.ozoptics.com/ALLNEW_PDF/DTS0135.pdf))
所以“780 沿 1517 通信用光纤走 16 km”不仅损耗巨大，而且模式与偏振行为也不在你当前模型覆盖范围内。

### 探测器“看不见 780”也确实常见，但不绝对

如果你用的是典型电信 InGaAs 探测方案，很多器件/模块的工作波段就写得很清楚：例如 Thorlabs 的 InGaAs APD 探测器给的范围是 **900–1700 nm**。([Thorlabs](https://www.thorlabs.com/free-space-ingaas-avalanche-photodetectors))（Excelitas 也有“1000–1700 nm”的类似口径。([Excelitas](https://www.excelitas.com/product-category/high-performance-ingaas-apds))）
这类探测器对 780 的响应确实可以认为“几乎没有”。

但如果你用的是 **SNSPD**，那它往往是**宽带**的，甚至可以覆盖 400 nm–2 µm，780 和 1550 都能探。([MRSEC at UT Austin](https://mrsec.utexas.edu/superconducting-nanowire-single-photon-detectors))
因此实验上通常会在 QFC 输出端用 **WDM/二向色镜/滤波腔**等把 780（以及泵浦、散射光）强力压下去——这也是你代码里 `apply_filter_780` 这个步骤的物理对应。

结论：你说“16 km 后 780 基本不可能贡献噪声”大概率正确；但这并不等于“仿真里可以把 780 留在系统 Hilbert 空间里，然后测量端当作不存在”。

## 2) 关键点：你代码里的 `apply_filter_780` 不是“探测器看不见”的替代，而是“让模型闭合”的必要条件

### 2.1 你的 bin Hilbert 空间明确包含 780 和 1517

你在 `basis.py` 里把 5D bin 定义成：
(|vac>, |H_{780}>, |V_{780}>, |H_{1517}>, |V_{1517}>)。

也就是说，**在态端如果不把 780 丢掉**，MPS 里确实可以存在 780 分量（比如 QFC 转换不完全时自然出现）。

### 2.2 但你的探测端 POVM / 到达投影 **只在 1517 的 3D 子空间上定义**

你用 `proj_3_from_5()` 把 5D 压到 telecom 的 ({|vac>,|H_{1517}>,|V_{1517}>})，对 780 分量是直接丢弃的：

```python
P[0,0]=1; P[1,3]=1; P[2,4]=1  # 780 那两维完全不进来
```

并且 `build_detection_effects_5d_by_bin()` 是把 6D→3D 的 effect 再 **embed 回3D 映射到 (|vac>,|H_{1517}>,|V_{1517}>) 三个分量上，**780 块上是零矩阵**。

这意味着：你的探测 POVM 在完整 5D×5D 空间上并不完备，它只在 1517 子空间上完备。

### 2.3 这就解释了“为什么 apply_filter_780=False 不自洽”

在量子测量语言里，“探测器看不子空间上是零”。

- “看不见 780”的正确 POVM 直觉是：
  **点击（click）effect 对 780 是 0**（因为不会被触发），
  但 **不点击（no-click）effect 在 780 上应该是 1**（因为它一定给出 no-click 结果）。
  这样才能保证 (\sum_{\text{all outcomes}} E = I) 在全空间成立。
- 你现在的实现是：
  **click effect 对 780 是 0**（没问题），
  **no-click effect 对 780 也是 0**（这就不是“看不见”，而是“这部分概率被模型丢了”）。

所以只要态里真的残留 780，那么对于“任何探测记录（包括 no-click）”，这一部分振幅都会给出 0 概率贡献，你就会看到：

- 概率不守恒（总概率 < 1），
- 或者更隐蔽地：你在用 MPS 收缩引擎算成功率/暗计数辅助概率时，会把“QFC 没转好 → 留在 780 → 探测端看到真空但可能暗计数触发”的那部分物理过程**错误地丢掉**。

而你的 `README` 也明确写了：**QFC/780 滤波在态端显式处理，探测端不再重复**。
这句话其实就等价于：探测端假设输入已经是“只剩 telecom 子空间”的有效态。

### 2.4 `apply_filter_780=True` 在你代码里做的正是“让这套假设成立”

## 1) 为什么我说 `apply_filter_780=False` 这条路径在你当前实现里不自洽

### 1.1 先说清楚：代码里 780 分量“确实会残留”，除非你显式把它丢掉

你每个 bin 的局域空间是 5D：

- `|vac>, |H_780>, |V_780>, |H_1517>, |V_1517>`

而 QFC 门是把 780 和 1517 做“类分束器旋转”的，所以 **只要 `θ` 不是 π/2，变换后就必然存在未转换的 780 幅度**（这不是噪声，是主效应：转换效率<1 的必然结果）。这点在你的 `qfc_gate()` 定义里非常明确：它在 (H780,H1517) 和 (V780,V1517) 两个子空间做 2D 旋转。

因此，在“全系统纯态”的层面上，如果你不做任何滤除/损耗，**系统态当然可以残留 780 分量**。你说“系统态根本不可能残留 780 分量”——这句话只在“你把 780 当作环境并已 trace out / 已完全损耗掉”的**约化态口径**下才成立。

### 1.2 `apply_filter_780` 在你代码里到底干了什么

在 `trajectory.apply_qfc_filter_memory_chain()` 里，`apply_filter_780=True` 时你会对每个 bin 在 QFC 后施加一个 Kraus 损耗通道：

- 关键是 `eta_780=0.0`：把 780 单光子**完全映射到真空（等效：被过滤/丢失）**
- 这个通道的定义也写得很清楚：它就是 5D 基序下“单光子 → 真空”的损耗 Kraus。

也就是说：
**`apply_filter_780=True` 让“未转换的 780”在态端就变成了“损耗（环境）”。**
这样你后面探测端只处理 1517 子空间就没有矛盾。

反过来，`apply_filter_780=False` 就意味着：**未转换的 780 幅度会一直留在 MPS 的 5D bin 账本里**（你也没有其它地方再把它干掉）。

### 1.3 不自洽点：你的探测 POVM / 到达统计是“只认识 1517 的 3D 子空间”

你探测端（包括到达统计）用的是 3D telecom 子空间 `{vac, H_1517, V_1517}`，然后嵌回 5D 时用的嵌入矩阵是：

- `embed_5_from_3()`：只把 (vac, H, V) 塞到 5D 的索引 (0,3,4)，**对 780 的索引 (1,2) 一律是 0**
- 同理 `embed_3d_to_5d()` 是用这个嵌入在双臂上做 Kronecker，仍然对 780 部分全是零。

这会导致一个关键后果：

> 在 `apply_filter_780=False` 的情况下，如果某个 bin 处在 `|H_780>` 或 `|V_780>`，那么 **所有探测结果（包括“空集=no click”）在你的 POVM 里对这部分的概率贡献都是 0**。

因为你构造的 effect 根本没有覆盖 780 子空间（它不是 “探测器对 780 不响应”，而是 “测量算符在 780 子空间为零，从而 POVM 不完备”）。`build_arrival_projectors_5d()` 和 `build_detection_effects_5d_by_bin()` 都是这个逻辑：先在 3D/6D 上构造，再嵌回 5D，而且嵌入只覆盖 1517。

**这就是我说的“不自洽”：**

- 物理上“探测器看不见 780”对应的是：
  `|H_780>` 出现时，探测器应该给出 **“no click”**（概率 1），而不是“任何结果概率都为 0”。
- 你现在的实现相当于：
  一旦存在 780，整条轨迹在探测端概率质量直接“蒸发”掉了（POVM 不闭合）。

所以我当时说的“不自洽”不是在说“780 会一路到探测器并形成噪声”，而是在说：**你现在这条分支把 780 当成了“既不损耗也不计入 no-click 的幽灵子空间”，概率论上站不住。**

## 2) 物理层面：780 到底会不会到中间站、会不会被探测到？

你直觉上说“780 不可能穿过 16 km 电信光纤并被 1517 探测器看到”，作为工程判断通常是对的，但这里有两个“依赖条件”：

### 2.1 光纤传输：780 的确会被压得很惨（尤其用标准电信单模纤）

电信单模纤（比如 SMF-28）是针对 1310/1550 nm 优化的，典型损耗窗口大致是：

- 1550 nm：~0.2 dB/km 量级 ([Berkeley Lab](https://www-eng.lbl.gov/~shuman/NEXT/CURRENT_DESIGN/TP/FO/Lect5-Optical fibers_2.pdf))
- 850 nm：~4 dB/km 量级（传统“第一窗口”）([Berkeley Lab](https://www-eng.lbl.gov/~shuman/NEXT/CURRENT_DESIGN/TP/FO/Lect5-Optical fibers_2.pdf))
- 780 nm 附近：在一些光纤规格里也能看到 ~4 dB/km 量级（当然这取决于纤芯/设计）。([Thorlabs](https://www.thorlabs.com/single-mode-fiber))

如果粗略拿 4 dB/km 估算，16 km 就是 64 dB 衰减，对应线性透过率约 `4×10^-7`；而 1550 nm 用 0.2 dB/km 则 16 km 约 3.2 dB，透过率 ~0.48。差异是 **百万倍** 量级。([Berkeley Lab](https://www-eng.lbl.gov/~shuman/NEXT/CURRENT_DESIGN/TP/FO/Lect5-Optical fibers_2.pdf))

此外，标准电信单模纤的截止波长在 ~1260 nm 左右，780 nm 在其设计工作带宽之外，模式/耦合也会更糟（额外抑制）。([MeetOptics](https://www.meetoptics.com/fiber-optics/bare-fibers/single-mode-fiber/s/thorlabs/p/SMF-28-J9?srsltid=AfmBOorw7dU7dz0Fyp57DFDw21OkGq1VHhQO05fQHXtwNRB-BdmumbxG))

所以从“能否形成可观噪声贡献”的角度，你的判断（“基本不可能”）非常合理。

### 2.2 探测器：**“完全看不见 780”不总是成立，取决于你用什么探测器**

- 如果你用 **InGaAs APD / InGaAs 探测器**，典型响应范围在 ~900/950–1700 nm，这确实基本不覆盖 780。([Hamamatsu Photonics](https://www.hamamatsu.com/jp/en/product/optical-sensors/apd/ingaas-apd.html))
- 但如果你用 **SNSPD**，很多系统在 780 和 1550 都能做到很高效率，且是宽带响应。([Tanopto](https://www.tanopto.com/wp-content/uploads/2020/07/tanopto-id281-brochure.pdf))

所以物理上“780 是否可能触发探测器”，得看你实验实际选型（以及中间是否有 WDM/窄带滤波把 780 彻底抑制）。但无论如何，在你这套仿真里，**更重要的是“你如何在数学上把 780 当成环境处理”**。

## 4) 关于 `v_res`：你对它的定位是对的，而且确实要防重复计入

你这段解释我完全同意：
`v_res` 本质上应当是“显式建模主要噪声后，仍然未建模的剩余可区分度/不可见失配”的一个残差项。

### 4.1 代码里 `v_res` 的数学含义是什么

在探测 effect 构造里，你做的是：

- 先构造“不可区分（int）”的 6D 两端口 POVM
- 再构造“带标签可区分（dist）”的 9D POVM，投影回 6D
- 然后按
  `E = v_res * E_int + (1 - v_res) * E_dist`
  混合

这就是非常标准的“用一个标量权重描述部分可区分/部分干涉”的 phenomenological 模型，在 HOM 干涉文献里属于常见口径。HOM 干涉的本质依赖于两光子的可区分性/模态重叠，偏离理想时干涉可见度会下降。([arXiv](https://arxiv.org/pdf/1711.00080))

你在 `detection.run_detection_pipeline()` 的注释里也明确写了 `v_res` 是“残差可区分度”。

### 4.2 你担心的“重复计入”风险确实存在

如果你已经显式建模了：

- 波包相对延迟/抖动（`delay_ns`, `delay_jitter_ns`）
- 偏振漂移（`U_A`, `U_B`）
- 相位/相位斜率/抖动（`phase_slope`, `phase_jitter_std`）
- 滤波腔/频率转换效率差异

那么这些都会在“实际两光子到达 BS 时的模态重叠”里产生主要的 HOM 可见度下降。你再让 `v_res` 去“吞掉 HOM 主效应”，确实很容易变成 **同一类失配被算两遍**。

### 4.3 我建议你把 `v_res` 固定成“真正的 residual”，避免逻辑混乱

一个很干净的使用原则：

- **原则 1：** `v_res` 不用于描述“你已在态里显式分辨的自由度”（时间 bin、偏振 Jones、已建模的相位漂移等）。
- **原则 2：** `v_res` 只用于描述“你没有显式建模的自由度上的模态不重叠”，比如：
  - 频谱/瞬时频率啁啾（而你只用时间 bin 近似了时域）
  - 空间模式/模式匹配残差
  - QFC 引入的额外频谱结构差异（你没显式上模态）
  - 任”

实践上可以这样落地：

- 跑 HOM 扫描（delay τ）时，先把 `v_res=1`，让曲线下降主要由你显式建模决定；
- 如果实验在 τ≈0 处仍然有一个“达不到的上限”（例如最高可见度永远到不了 1），再用 `v_res<1` 来吃掉这部分“非时间/非偏振”的残差。

这样 `v_res` 就不会变成一个“万能可见度旋钮”，也不会和你显式噪声打架。
