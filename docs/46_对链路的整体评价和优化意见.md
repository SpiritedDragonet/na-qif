# 1) 必须立刻修的硬错误：`v_res` 的“可区分光子模型”构造是错的

## 1.1 你现在的实现方式（问题点）

在 `build_detection_effects_5d_by_bin()` 里，如果 `v_res < 1`，你会：

1. 构造 9D（带标签）探测 POVM
2. 通过 `embed_9_from_6()` / `reduce_9d_effects_to_6d()` 把 9D effect **投影回 6D**
3. 再用 `mix_effects(..., v_res)` 在 6D 层做凸组合
4. 最后投影到 3D 单光子输入空间（`project_6d_to_3d`）

关键问题在于：

- `embed_9_from_6()` 的定义是把 6D 的 |H>,|V> 映射为 **(a+b)/√2 的对称态**（也就是 boson 对称化的 embedding）
- 但“可区分光子”模型在输入端的物理含义是：
  **A 臂的光子是 label-a，B 臂的光子是 label-b**（来源标签与空间臂绑定）
  而不是 `(a+b)/√2` 的对称叠加。

因此你现在做的 `reduce_9d_effects_to_6d` 相当于用“错误的嵌入”去回投影，导致：

- 在 `v_res=0`（完全可区分）极限下，POVM 在输入 3D×3D 子空间上**不再完备**
- 典型的 HOM 经典结果（两光子 |H,H> 入射 50/50 BS，输出 coincidence 50%）会被你算成 0（我用你代码现有实现验证过）。

> 你在 `run_detection_self_checks()` 里做的自检并没有发现这个问题，因为自检只验证了你“自己的回投影逻辑”在内部一致（即 v_res=0 就等于你构造的 reduced_dist），但没有验证 reduced_dist 是否等价于物理上正确的“可区分极限”。

## 1) 先回答你关心的物理事实：780 在这条链路上基本就是“必然丢掉”

### 光纤本身并不是“只让 1517 过”的理想带通

石英光纤不是一条窄带滤波器，它在可见到近红外都有传输窗口；但**损耗随波长变短会显著上升**，主要原因之一是 Rayleigh 散射大致按 ( \lambda^{-4} ) 增强。([MSU Web Physics](https://web.pa.msu.edu/courses/2011fall/PHY431/Labs/QuantumOptics/Components/Optics/Fiber Optics/Fiber Optic Basics.pdf))

对“780 nm 能不能在光纤里传 16 km”这个问题：
即便用**专门支持 780–970 nm 的单模光纤**，Thorlabs 给的最大衰减也到 **≤ 4.0 dB/km @ 780 nm**。([Thorlabs](https://www.thorlabs.com/single-mode-fiber))
那 16 km 就是 **≥ 64 dB** 的额外损耗量级（透过率 (\sim 10^{-6.4}\approx 4\times 10^{-7})），还没算连接器/熔接/器件的额外抑制。也就是说，从“链路透过率”角度，它确实可以视作**极小量**。

更贴近你实验的情况是：你用的是**电信链路光纤**（例如 SMF-28 类）来跑 1517 nm。对这种“设计工作在 1.3/1.55 µm 的单模光纤”，在**低于截止波长**使用时会开始呈现多模特性、模式不稳定等问题；工程文档通常会明确说“短于 cutoff 就不再单模，会像多模那样工作”。([OZ Optics](https://www.ozoptics.com/ALLNEW_PDF/DTS0135.pdf))
所以“780 沿 1517 通信用光纤走 16 km”不仅损耗巨大，而且模式与偏振行为也不在你当前模型覆盖范围内。

### 探测器“看不见 780”也确实常见，但不绝对

如果你用的是典型电信 InGaAs 探测方案，很多器件/模块的工作波段就写得很清楚：例如 Thorlabs 的 InGaAs APD 探测器给的范围是 **900–1700 nm**。([Thorlabs](https://www.thorlabs.com/free-space-ingaas-avalanche-photodetectors))（Excelitas 也有“1000–1700 nm”的类似口径。([Excelitas](https://www.excelitas.com/product-category/high-performance-ingaas-apds))）
这类探测器对 780 的响应确实可以认为“几乎没有”。

但如果你用的是 **SNSPD**，那它往往是**宽带**的，甚至可以覆盖 400 nm–2 µm，780 和 1550 都能探。([MRSEC at UT Austin](https://mrsec.utexas.edu/superconducting-nanowire-single-photon-detectors))
因此实验上通常会在 QFC 输出端用 **WDM/二向色镜/滤波腔**等把 780（以及泵浦、散射光）强力压下去——这也是你代码里 `apply_filter_780` 这个步骤的物理对应。

结论：你说“16 km 后 780 基本不可能贡献噪声”大概率正确；但这并不等于“仿真里可以把 780 留在系统 Hilbert 空间里，然后测量端当作不存在”。

## 2) 关键点：你代码里的 `apply_filter_780` 不是“探测器看不见”的替代，而是“让模型闭合”的必要条件

### 2.1 你的 bin Hilbert 空间明确包含 780 和 1517

你在 `basis.py` 里把 5D bin 定义成：
(|vac>, |H_{780}>, |V_{780}>, |H_{1517}>, |V_{1517}>)。

也就是说，**在态端如果不把 780 丢掉**，MPS 里确实可以存在 780 分量（比如 QFC 转换不完全时自然出现）。

### 2.2 但你的探测端 POVM / 到达投影 **只在 1517 的 3D 子空间上定义**

你用 `proj_3_from_5()` 把 5D 压到 telecom 的 ({|vac>,|H_{1517}>,|V_{1517}>})，对 780 分量是直接丢弃的：

```python
P[0,0]=1; P[1,3]=1; P[2,4]=1  # 780 那两维完全不进来
```

并且 `build_detection_effects_5d_by_bin()` 是把 6D→3D 的 effect 再 **embed 回3D 映射到 (|vac>,|H_{1517}>,|V_{1517}>) 三个分量上，**780 块上是零矩阵**。

这意味着：你的探测 POVM 在完整 5D×5D 空间上并不完备，它只在 1517 子空间上完备。

### 2.3 这就解释了“为什么 apply_filter_780=False 不自洽”

在量子测量语言里，“探测器看不子空间上是零”。

- “看不见 780”的正确 POVM 直觉是：
  **点击（click）effect 对 780 是 0**（因为不会被触发），
  但 **不点击（no-click）effect 在 780 上应该是 1**（因为它一定给出 no-click 结果）。
  这样才能保证 (\sum_{\text{all outcomes}} E = I) 在全空间成立。
- 你现在的实现是：
  **click effect 对 780 是 0**（没问题），
  **no-click effect 对 780 也是 0**（这就不是“看不见”，而是“这部分概率被模型丢了”）。

所以只要态里真的残留 780，那么对于“任何探测记录（包括 no-click）”，这一部分振幅都会给出 0 概率贡献，你就会看到：

- 概率不守恒（总概率 < 1），
- 或者更隐蔽地：你在用 MPS 收缩引擎算成功率/暗计数辅助概率时，会把“QFC 没转好 → 留在 780 → 探测端看到真空但可能暗计数触发”的那部分物理过程**错误地丢掉**。

而你的 `README` 也明确写了：**QFC/780 滤波在态端显式处理，探测端不再重复**。
这句话其实就等价于：探测端假设输入已经是“只剩 telecom 子空间”的有效态。

### 2.4 `apply_filter_780=True` 在你代码里做的正是“让这套假设成立”

`apply_qfc_filter_memory_chain()` 里，如果 `apply_filter_780` 为 True，你会对每个 bin 施加：

- `loss_channel_both_subspaces(eta_780=0.0, eta_H_1517=eta_peak, eta_V_1517=eta_peak)`
  这会把任何 780 光子**通过损耗 Kraus 映射到真空**（并且顺便给 1517 加上 `eta_peak` 的插入损端 POVM 适用的有效子空间里，模型闭合。

------

## 3) 你“探测器看不见 780，所以不需要滤”的直觉哪里差了一步？

差的那一步是：**“看不见” ≠ “可以在系统 Hilbert 空间里一直保留且不处理”**。

- 如果 780 分量在物理上被滤波器吸收/散射掉，它就是一个**不可逆损耗通道**：必须在态上体现为 Kraus map（相当于把这部分自由度送入环境并 trace out）。你现在的 `loss_channel_both_subspaces(eta_780=0)` 就是在做这件事。
- 如果你想建模的是“780 真的一路飞到探测器附近，但探测器完全盲”，那也可以，但你必须把探测 POVM 改成“no-click 在 780 子空间上是 identity”，保证 POVM 完备。你现在的做法不是这种物理。
- 如果你想建模的是“780 走进电信光纤，但 16 km 后几乎全没了”，那也可以，但你必须给 780 加一个**极强的光纤损耗通道**（而你现在 fiber/Jones/loss 全部是 1517-only，通过 3D 子空间实现的）。

所以，“780 不会对噪声贡献”并不能推出 “`apply_filter_780=False` 是物理一致的”。它只推出：**780 应该被建模成“极强损耗→真空”的环境通道**，也就是你现在默认 `apply_filter_780=True` 的逻辑。

## 4) 这条 flag 最合理的定位：要么只用于 debug，要么改成“可调抑制度”而不是 bool

如果你的目的是“尽可能真实指导实验”，我建议：

### 建议 A（最简单、也最贴近你现有架构）

把 `apply_filter_780` 视为“必须为 True 的实验配置”，**不要在物理结果扫描里关掉它**。
因为你的探测端/光纤端现在就是以“780 已被态端滤掉”为前提搭的（你 README 里也这么写了）。

### 建议 B（如果你真的想研究滤波不足对噪声的影响）

把 `apply_filter_780: bool` 升级成一个连续参数，比如：

- `eta_780_residual`（或者以 dB 表示的 extinction ratio），让它可以非常小但不为 0；
- 同时把这部分 residual 780 的后续处理也一致化：要么直接在态端把它也作为损耗（等价于更强滤波），要么把探测端 no-click 在 780 上补成 identity。

> 注意：如果你后续噪声模型里包括泵浦诱导的 broadband 噪声，那一类噪声是**在 1517 波段生成**的（或被滤波腔带宽截取），它和“残留 780 本身”是两码事。残留 780 的主要效应通常是“降低成功率/引入未监测自由度导致退相干”，而不是“直接加拟极端情况：SNSPD + 滤波不够）
> 那就不能只靠 `apply_filter_780` 开关了，你需要把探测端改成**光谱相关**：

- 780 经过链路（WDM/滤波/光纤）剩多少；
- SNSPD 对 780 的系统效率是多少；([MRSEC at UT Austin](https://mrsec.utexas.edu/superconducting-nanowire-single-photon-detectors))
- 这些残留会不会与 1517 的 BSM 事件形成误符合。

但就你说的“16 km 电信光纤”，这条路径通常会被链路损耗和滤波压到很小。

## 5) 用一句话总结你问的点

你说的“780 走不到探测器、探测器也看不见，所以不会形成噪声贡献”本身没问题；
**问题在于你当前实现里**，当 `apply_filter_780=False` 时，780 分量既没有被当作“强损耗→真空”处理，也没有被当作“盲探测→必然 no-click”处理，而是被探测 POVM 直接当成“测量空间之外的东西”丢掉了，于是模型在概率与噪声统计口径上不闭合。
