我把你现在“相位可视化”的实现顺着代码看了一遍，问题基本不在“强度”，而在你定义的“相位”本身（以及亮度和相位来自不同物理量的混搭），所以才会出现你说的“强度看起来没问题，但相位在 0 和 π 之间随机跳”。

第一，代码里你取的“相位”其实是“与真空的相干项相位”，而不是你直觉里那种“波包的复振幅相位”。在 `extract_bin_state_coherences()` 里你做的是：对每个 bin 取单站点约化密度矩阵 `rho_A`，然后令 `phase = arg(rho_A[0, k])`（0 对应 |vac,vac>）。也就是说，你画的是“真空态 |vac,vac> 与每个局域基态 |k> 之间的相干项”的相位。

第二，你在 HSV 映射里用“对角概率”当亮度，但用“真空相干项”当色相，这在物理上通常是不匹配的，正是导致“亮着但颜色乱”的直接原因：
`_probs_phases_to_rgb_image()` 的 Value 通道用的是 `values = (probs/max_prob)**value_power`，也就是对角概率的函数；而 Hue 用的是你从 `rho[0,k]` 提取出来的相位。`plot_dual_arm_heatmap_phase()` 也是把 `probs` 和 `phases` 直接喂给这个 HSV 函数。所以当某个状态的“概率很大”但“与真空的相干几乎为 0”时，你就会得到：亮度很高（因为 prob 大），但色相其实来自一个接近 0 的复数（数值噪声主导），于是颜色看起来“随机”。

第三，为什么会具体表现为只在 0 和 π 跳？这通常意味着你取相位的那个复数“几乎是纯实数”，而且正负号在数值误差/截断误差下会翻来覆去：`np.angle(x)` 对正实数给 0，对负实数给 π。你现在的相位来自 `rho[0,k]`；在你这类发射–探测网络里，`rho[0,k]` 很容易在物理上就接近 0（甚至理想情况下严格为 0），原因是“真空分量”和“出光子分量”往往与系统（原子、或其他未观测自由度）处在正交的“哪条路径”标记态上：
举个最典型的结构：若全局态近似形如
$$
|\Psi\rangle = \alpha,|e\rangle_{\rm atom},|{\rm vac}\rangle_{\rm field} + \beta,|g\rangle_{\rm atom},|1\rangle_{\rm field},
$$
对原子做偏迹后，场的约化态里真空–单光子相干项正比于 $\alpha\beta^*\langle e|g\rangle = 0$。这时 `rho_field[0,1]` 在物理上就应当为 0，于是你去取它的 `angle` 得到的只能是“数值残差的符号”，自然会在 0/π 之间看似随机。

你现在看到的现象，严格地说更像是：你在用一个“本来就应当很小/为零的相干项”的相位去给一个“概率很大的对角项”着色，因此视觉上会非常不稳定。这不是“强度提取没问题但相位算法错了”那么简单，而是“你选的相位定义在当前物理态上大概率不可观/不可用”。

你可以按你真正想看的东西，选下面两条路线之一。

路线 A：如果你就是想画“与真空的相干项”这件事（coherence heatmap），那你的实现需要做两件最小改动

1. 亮度（Value）应该来自 $|\rho[0,k]|$，而不是来自 $\rho[k,k]$。你自己在函数说明里也写了“Value ∝ |coherence|^value_power”，但实现里实际用了 prob。这一点是实质 bug（至少是“实现与自我定义不一致”）。
   最小修法是：在 `extract_bin_state_coherences()` 里同时算出 `coh = rho[0,:]`，然后传 `abs(coh)` 作为 Value 的输入，`angle(coh)` 作为 Hue。
2. 给相位加阈值掩膜。只要 $|\rho[0,k]|$ 很小，相位就是数值噪声；你应该把这类点直接置黑（Value=0）或把 Hue 固定为 0（无意义但不乱跳）。否则你永远会在暗噪声/截断误差上看到“随机色块”。

用伪代码表达就是：

- 取 `coh = rho[0, :]`
- `amp = abs(coh)`；`phase = angle(coh)`
- 若 `amp < eps`：令 `amp = 0` 且 `phase = 0`（或 mask）
- HSV：Hue=phase，Value=amp^power（归一化后）

这样你会发现：在你现在这类“原子–光子纠缠的发射态 +（以及后续损耗/探测导致的混态）”里，大部分 bin 的“真空相干”会很暗，这是物理上合理的结果，而不是坏事。

路线 B：如果你真正想看的是“波包的相位”或“光纤相位漂移是否被引入”，那你现在这个相位定义本身就不对

你现在画的 `arg(rho[0,k])` 只会对“存在真空–单光子相干”的态敏感，也就是类似 $(|0\rangle + e^{i\phi}|1\rangle)/\sqrt{2}$ 这种态；但你系统里主角是单光子/双光子 Fock 分量（并且常常和原子纠缠），对这类态：

- “绝对光学相位”本来就不是一个在密度矩阵里能被单臂单站点看到的量；
- 你在光纤里加的那种“对整个 Jones 矩阵乘一个全局相位”只是在单光子子空间上整体乘 $e^{i\phi}$，对纯一光子密度矩阵 $|1\rangle\langle 1|$ 是完全不可见的$它只会改变 $|1\rangle\langle 0|$ 这类相干项，但这些项本来就没有/被偏迹掉了$。这也解释了你在某些 stage 里“强度没变，但相位看起来乱/看不出你以为的漂移”。

如果你的目标是“和干涉/BSM相关的相位信息”，更合理的是看一阶相干（或等效的模式函数）：

- 计算同一臂不同 bin 的一阶相关矩阵
  $$
  G_{nm}=\langle c_n^\dagger c_m\rangle,
  $$
  单光子纯态时 (G) 近似秩 1，可写成 $G_{nm}=\xi_n^*\xi_m$，这时 $\xi_n$ 的相位才是“波包相位”。
- 或者更省事：选一个参考 bin $n_0$，只算 $g_n=\langle c_{n_0}^\dagger c_n\rangle$，画 $\arg(g_n)$。这给的是“相对相位”，并且只在强度足够处有意义。

这类量和 HOM/BSM 的可见度、模式重叠是同一套物理对象；也更接近你最终关心的“可干涉性/保真度退化原因”，而不是“与真空的相干”。

最后给你一个快速自测，能立刻判断是“可视化定义问题”还是“你以为应该有相位其实物理上没有”：

- 人工准备一个确实有真空相干的单站点态，比如在某个 bin 上造 $(|{\rm vac}\rangle+|H\rangle)/\sqrt{2}$（其余全真空），然后只跑你的一段 Jones/phase gate。
  如果这时你的 `arg(rho[0,H])` 能稳定地显示相位随 gate 改变，那说明你的画图代码本身没大错；你现在之所以“随机 0/π”，就是因为在真实发射态里 $\rho[0,k]$ 物理上接近 0。
