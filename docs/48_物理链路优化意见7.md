## 0) 先把你当前程序的“物理管线”说清楚（方便对照定位）

你现在的主链路基本是：

1. **双原子发射（780nm）**：用 time-bin collision model + TEBD，在链上把两个 emitter（12 维 = 原子 4 × 腔 3）逐步与每个时间 bin（5 维：vac、H780、V780、H1517、V1517）作用；内禀损耗/自发辐射用 Kraus（量子轨迹）采样。
2. **QFC（780→1517）**：每个 bin 里做一个 780↔1517率 θ = asin(sqrt η)），并带极化相位 φ_H/φ_V。
3. **滤波腔（可选 memory chain）**：在每臂末端追加一个 3 维 unitary 把滤波器的单极点响应做成跨 bin 的“记忆”。
4. **光纤（不在态上作用）**：采样 Jones 矩阵、PDL/损耗、相位漂移/频偏（phase slope）/相位抖动等，作为后面 POVM 的参数（海森堡推回）。
5. **中间站 BSM（不在态上作用）**：用 6D（含 0/1/2 光子）端口空间构造 BS unitary，再把探测 POVM（含阈值探测器效率、内禀暗计数、部分可分辨 v_res、背景 OR-map）推回到输入的 3D×3D（每臂 telecom 子空间 vac/H/V）并嵌入 5D。
6. **收缩求概率/条件保真度/CHSH**：用 contraction engine 对每个 bin（同 bin 和跨 bin 符合 coincidence window 的记录）求 p_success、真/假分解、对 Bell 投影保真度、Pauli 相关与 S_max（Horodecki）。

这个总览和你描述的实验链路是匹配的。

## 1) 优先级最高：我认为“会直接把结果带偏”的问题（建议先改）

### 1.1 背景噪声（bg_source）现在**语义混乱 + 很可能双重计入链路损耗/探测效率/BS 分束**

你在 detection 里把背景当成“源端背景概率（每 bin）”，然后用 `_scale_source_background_map` 乘以每臂传输 eta_arm，再按 BS θ 分束并在端口上平均分给 H/V。

问题在于：你在上游构造 `p_bg_bin_map` 时（从噪声谱密度或直接给 ran 和 eta_det_map 乘进去了**（至少默认 QFC 噪声那段是这样设计的），等于那时它更像是“探测端点击率”。然后 detection 里又乘了一遍 `eta_arm`（光纤损耗）并再做 BS 分束，逻辑上就变成“从探测端又倒推回源端再推一次”，很容易出现：

- **链路损耗被乘两遍**（eta_link_mean × eta_arm，其中 eta_arm 本身已包含均值），导致背景被严重低估；
- **探测效率在端口之间不一致时被处理错**：你在 `_scale_source_background_map` 里把 H1/V1、H2/V2 先平均掉再平分回去，这会把不同探测器效率差异给抹掉（甚至把 arm A 的噪声“转移到”另一端口探测器时也没有换用对应 η_det）。

这类错误会直接影响你最关心的：**“保真度随长度/噪声衰减”的趋势**（因为 bg主要瓶颈之一）。

**建议你立刻做一个语义拆分（强烈建议）**：

- 把背景分成两类（在配置层面和变量名层面都分开）：
  1. `bg_rate_source_arm_hz`（每臂、进入光纤前、滤波后、在 telecom 模式里的噪声光子到达率；不含链路、不含探测器）
  2. `bg_rate_detector_hz`（每个探测器通道的等效点击率；如果你有直接测得的计数率，用这个）
- 在 detection 里只做一件事：
  - 如果给的是 `bg_rate_source_arm_hz`：**在 detection 里乘链路损耗、BS 分束、再乘各通道 η_det**，最后转换成每 bin 点击概率 OR-map。
  - 如果给的是 `bg_rate_detector_hz`：**直接转 p_bg_detector_bin_map，完全不再做 `_scale_source_background_map`**（或让它变成恒等）。

你现在这套 OR-map 背景注入本身作为“低阶近似”是合理的（噪声如果是非相干的，确实可以当作独立点击过程），但前提是“概率定义在哪里”必须一致。
另外，从物理上讲，QFC 噪声常常需要强谱滤波来抑制并提升 SNR，这一类“噪声随滤波带宽线性缩放”的建模方向是对的。([Optica Publishing Group](https://opg.optica.org/optica/fulltext.cfm?uri=optica-5-5-507&utm_source=chatgpt.com))

### 1.4 光纤长度 `length_km` 同时用于“光子链路损耗”和“原子等待退相干时间”，但默认尺度可能不对

你现在把等待时间设为 `t_wait = (length / v_g) * scale + offset`，默认 `scale=1`。而中间站 BSM 的 herald 回传到两端，通常等待时间更接近 **往返**（≈ 2L/v_g），还要加处理延迟。你虽然留了 `t_wait_length_scale`，但默认值会让退相干偏乐观。

另外，如果你把 `length_km` 当“节点间总距离”，那每臂只有一半；如果当“每臂到中间站距离”，那链路损耗就该用每臂长度。**这两个在你的模型里目前绑死在同一个变量上**，很容易在 length scan 时无意间把其中一项算错一倍。

**建议**：把参数拆成两个：

- `L_arm_km`：每臂光子传输距离（用于损耗、相位噪声/PDL 等）
- `L_classical_km` 或直接 `t_wait_us`：用于原子存储退相干（往返可设为 2*L_arm/v + electronics）

这样你做 16 km/臂 的实验时不会再靠“把 length 设成 33 km 来偷偷补 2 倍时间”这种不透明的 workaround。

## 2) 中优先级：会明显影响“对实验的指导意义”的建模简化/缺项

### 2.1 你的“部分不可分辨度 v_res”是一个**经验混合模型**，要避免与“真实物理失配参数”双重计数

你在构造 POVM 时，用 `v_res` 在“完全不可分辨（6D）”与“完全可分辨（9D labeled）”之间做凸混合。
这在工程上常用、也确实能把 HOM 可见度不足等效进去，但需要注意两点：

1. **如果你已经显式模拟了导致失配的机制**（例如：两臂波包不同、delay、phase slope/抖动、滤波腔 detuning 不同），那么这些机制已经会在 MPSv_res<1` 会**双重惩罚**。
2. v_res 的物理含义最好被“锚定到可测量量”，最典型就是 HOM dip 的可见度与模重叠。两单光子在 50/50 BS 的 coincidence 与模重叠 |⟨ψ_A|ψ_B⟩|^2 的关系，是量子光学里非常标准的结果。([arXiv](https://arxiv.org/pdf/1711.00080?utm_source=chatgpt.com))
   你应该明确：v_res 是“剩余的、未被模型显式捕获的模失配”（比如空间模、频谱细结构、偏振补偿误差等），并且用实验测到的 HOM 可见度去标定它。

**建议（强）**：做一个“只开显式机制（delay、phase slope、滤波 detuning 等），把 v_res=1”的 HOM 扫描（你已经有 hom.py），把得到的可见度与实验对比；若仍有差距，再把差距吸进 v_res。

### 2.2 探测器模型缺少“对 coincidence window 很敏感”的几个现实因素

你现在的探测器模型包括：

- η_det（效率）
- 内禀暗计数（按 gate 换算到 bin）
- 背景 OR-map
- 计数是阈值型（6D/9D 里等效实现）

但以下对“窗口优化/误报率”很关键的现实因素没进来：

- **时间抖动（timing jitter）**：会把本应同 bin 的双击分散到邻近 bin，从而改变“同 bin vs diff bin”占比，直接影响你现在用来扫描的 coincidence_window。
  做法可以很简单：在采样 click bin 时对 bin index 做一个离散高斯卷积（或在构造跨 bin 记录时把响应核做成非对角）。不需要把 MPS 的物理态变得更复杂。
- **死时间 / afterpulsing**：对双击率和误报有影响，尤其当你 gate 很密、或者背景较高时。

这些因素如果不进来，你用仿真去“选 window_ns/阈值/采样策略”时，指导意义会弱。

### 3.3 轨迹采样 vs “直接用 CPTP 平均”两种模式建议明确分开

你发射部分用量子轨迹 Kraus 采样（每 run 得到一个纯态），然后 detection 用精确收缩求概率，再对 runs 做平均，这是可行的 Monte Carlo。

- **轨迹模式**：用于大规模扫描。

至少把这两种模式在接口层面区分清楚，避免以后你以为是“数值误差”，其实是“MC 方差”。

## 4) 你现在输出的数据“够不够指导实验”？我认为：核心够，但缺 3 类关键输出

你目前已经输出了很多“该有的”核心指标：
p_arrive、p_success_true/false、fidelity_true/all/false、CHSH S_max、acceptance、bg/dark assisted 分解等（summary.py 的汇总也比较全）。这些对误差预算已经很有用。

但如果目标是“直接指导实验怎么调”，我建议再补三类输出（优先级从高到低）：

### 4.1 **时间域诊断**（用来决定 gating / coincidence window / delay 补偿）

你需要输出（至少存成数组或直方图）：

- 单臂光子到达时间分布（或 per-bin 强度）：I_A[n], I_B[n]（按物理时间顺序！）
- 触发两击记录的 Δbin 分布（同 bin vs ±1 bin vs …）在不同 window_ns 下的变化
- 成功事件中“同 bin 成功”和“diff bin 成功”的占比（以及对应 fidelity）

没有这些，你只能盲扫 window_ns，却看不出“为什么最优 window 在某处”。

### 4.2 **把 v_res 与 HOM/模重叠挂钩的可观测量**

你已经有 hom_scan，但建议在每次 run 里直接输出：

- 归一化模重叠：`M = |∑_n f_A[n] f_B*[n]|^2`（或在你的离散 bin 基里对应的 overlap）
- 理想 HOM 可见度预测（在无额外 v_res 情况下）

这样你能把“波包失配、phase slope、delay jitter、滤波 detuning”等直接变成一个实验可测的 HOM 曲线（HOM dip 这是最直接能对齐实验的东西）。([arXiv](https://arxiv.org/pdf/1711.00080?utm_source=chatgpt.com))

### 4.3 **把“每秒纠缠率”算出来，而不只是每 attempt 概率**

实验上最终关心的是：

- herald 成功率（Hz）
- 在这个率下得到的 Bell 对保真度/CHSH

你现在有 `herald_rate_abs` 这类字段，但它看起来更像“每 attempt 的概率”。建议你显式输出：

- `T_attempt ≈ (往返飞行时间 + 本地序列时间 + 处理延迟)`
- `R_ent = p_success_abs / T_attempt`

这样 length scan 就能直接变成“距离 vs 纠缠率 vs fidelity”的三维 tradeoff 曲线，对实验决策非常直接。
