## 1) 先别谈性能：你这里有几处“硬逻辑/接口不一致”，会让结果不可信

### 1.1 `run_dual_atom_emission()` 的 swap 顺序是错的（而且会导致 site 索引跟实际 MPS 排列脱节）

在 `trajectory.py::run_dual_atom_emission` 的主循环里，你写的是：

```python
mps.swap_sites(site_atomA - 2)
mps.swap_sites(site_atomA - 1)
site_atomA -= 2
...
mps.swap_sites(site_atomB - 2)
mps.swap_sites(site_atomB - 1)
site_atomB -= 2
```

但 `TenPy` 的 `MPS.swap_sites(i)` 语义是**交换第 i 和 i+1 个 site**。([TeNPy](https://tenpy.readthedocs.io/en/v1.0.5/reference/tenpy.networks.mps.MPS.html))
所以你现在这两次 swap 的第 1 次根本**不包含 atom site**（只是在交换 atom 左边的两个 bin），第 2 次才把 atom 往左挪 1 格。结果就是：

- atom 实际只左移了 1 个 site；
- 你却 `site_atomA -= 2`，从此 `site_atomA` 变量不再指向 atom；
- 下一步你用错误的 site 去做 `apply_bond_op(site_binA, emission_gate)`，理论上应该直接维度不匹配崩掉；更糟的是如果某些情况下维度碰巧匹配（比如两个 bin 都是 5 维），你会“悄悄把门打到了 bin-bin 上”，物理就彻底错了。

**正确的 swap 顺序**（让 atom 真的跨过两个 site）应该是：先 swap 它与左邻居，再 swap 它与新的左邻居，也就是：

```python
# move atomA left by 2
mps.swap_sites(site_atomA - 1)   # 这一步 atomA 左移 1
mps.swap_sites(site_atomA - 2)   # 这一步 atomA 再左移 1
site_atomA -= 2
# move atomB left by 2
mps.swap_sites(site_atomB - 1)
mps.swap_sites(site_atomB - 2)
site_atomB -= 2
```

这个顺序我用“只跟踪标签的离散交换”推演过，确实能把布局一路维持成你后续 QFC/检测所假设的那种结构：循环结束后会得到
`A1, atomA, B1, atomB, A2, B2, ..., AN, BN`。

> 强烈建议你立刻在 debug 模式下加 invariant：
>
> - 每次 swap 之后断言 `mps.d[site_atomA] == 12`、`mps.d[site_atomB] == 12`；
> - 每次进入下一轮之前断言 `mps.d[site_atomA-1] == BIN_DIM`、`mps.d[site_atomB-1] == BIN_DIM`；
>   这样 swap 链路一旦再改坏，立刻爆炸，不会悄悄算错。

### 1.2 `run_dual_atom_emission()` 循环结束后的“收尾 swap”不够：你要得到 `[atomA, atomB, A1, B1, ...]` 还差两步

你目前循环后只做了：

```python
mps.swap_sites(site_atomB - 1)
site_atomB -= 1
```

在“正确 swap 顺序”的版本下，循环结束布局是
`A1, atomA, B1, atomB, A2, B2, ...`，并且 `site_atomA=1, site_atomB=3`。

这时**只做一次** `swap_sites(site_atomB-1)`（即 swap B1 与 atomB）会得到
`A1, atomA, atomB, B1, ...`，还没把 atoms 挪到最左边，后面 `apply_qfc_filter_memory_chain`（它假设 bins 从 site=2 开始）会立刻错位。

要收尾成你后续全链路假设的布局（`[atomA, atomB, A1, B1, ...]`），最稳的三步是：

```python
# 1) swap B1 <-> atomB
mps.swap_sites(site_atomB - 1); site_atomB -= 1   # 3->2
# 2) swap A1 <-> atomA
mps.swap_sites(site_atomA - 1); site_atomA -= 1   # 1->0
# 3) swap A1 <-> atomB  (此时 atomB 在 site_atomB=2)
mps.swap_sites(site_atomB - 1); site_atomB -= 1   # 2->1
```

最终布局：`atomA, atomB, A1, B1, A2, B2, ...`，这才和你后面 `qfc_filter`/`detection` 的 site 约定一致。

### 1.3 Fiber phase jitter：`sample_fiber_realization()` 返回的是“数组”，但 detection 端当成“标量 std”用（接口不自洽）

## 2) 你 46 分钟/单跑的最大性能黑洞：发射循环里每个 bin 都在 `canonicalize()` 全链扫描

在 `run_dual_atom_emission()` 里，你每个 time bin 都对 atomA/atomB 做了 Kraus loss（量子跳跃），然后：

```python
mps.canonicalize(renormalize=True)
```

这一步是**全链 canonical_form_finite 扫描**，复杂度大致是 O(L) 次分解/QR/SVD（L~2*n_bins+2），你在 N~200 时等于做了 200 次全链 sweep，这几乎必然就是你 46 分钟的主因。

TenPy 的 canonical form / 正交中心重定位这类操作本来就不是给“每个 dt 都扫全链”用的；`swap_sites` 的文档也明确它是在 MPS 上就地交换相邻站点，配合局部截断使用。([TeNPy](https://tenpy.readthedocs.io/en/v1.0.5/reference/tenpy.networks.mps.MPS.html))

### 2.1 不降真实性、但把运行时间砍掉一个数量级的做法：把“loss Kraus”并入同一步的两体更新里，只做一次局部 SVD

你现在的流程是：

1. 对 (bin, atom) 做 emission gate（两体 unitary）→ 一次 `set_svd_theta`
2. 对 atom 做 loss channel（单体 Kraus）→ 你用 `set_B(..., form="Th")` 改了张量
3. 为了修复 canonical 结构 → `canonicalize()` 扫全链

最推荐的改法是：
**把 (I_bin ⊗ K_mu) 直接作用在 bond 的 θ 上，然后只做一次 `set_svd_theta`**。也就是：

- 先拿到 bond θ（`get_theta(i, n=2)`），对物理腿作用 emission unitary；
- 在同一个 θ 上计算每个 Kraus 的概率并采样 mu；
- 把采样到的 Kraus 作用到 θ 的 atom 物理腿；
- 最后 `set_svd_theta(i, theta_after, trunc_par=...)` 完事。

这样每个 bin 每个臂的“unitary + loss jump”只需要**一次局部 SVD**，完全不需要全链 canonicalize。

这一步对物理严格性没有任何损失：你仍然是在做标准的离散时间量子轨迹更新（collision model / QSDE 的离散化）。([arXiv](https://arxiv.org/pdf/0804.0806))

> 你在 `mps.py::MPSState.apply_bond_op()` 已经有 “取 θ → 作用 op → set_svd_theta” 的框架了。建议新增一个专门函数，比如：
>
> - `apply_bond_op_then_kraus_on_right(i, U, kraus_ops_right, rng, trunc)`
>   然后在 emission 循环里替代 “apply_bond_op + apply_kraus_one_site + canonicalize”。

这一个改动通常就足够把单跑从“几十分钟”压到“十几分钟量级”（具体取决于 chi、dt、机器 BLAS 等），而且是最“干净”的提速：不牺牲物理，反而更接近 TEBD 的本来用法。

### 2.2 进一步提速：把 loss Kraus 预先构建并缓存，避免每个 bin 反复造 list/矩阵

你目前在循环外已经构了 `loss_kraus_A/B`，这点不错。再往前一步是：

- emission gate 的构建里 `expm(generator)` 每步都做；这通常不是最大头，但如果 canonicalize 去掉后它可能变成显著开销。
- 可以考虑把 A/B 的 `omega(t)` 先算成数组，`h_atom(t)` 也缓存，然后 gate 构建减少 Python overhead。
- 还可以把 `generator` 的稀疏结构利用起来（block 形式），但这属于二期优化。

### 2.3 探测抽样阶段（如果你 shots 很大）还有一个“立刻减半甚至数量级”的优化

在 `detection.run_detection_pipeline()` 的抽样部分，你对每个 sample（即每个双击记录）都算一次 `qubit_state = engine.compute_record_qubit_state(...)`，这内部是 **16 次 contraction**（为 4×4 密度矩阵的每个元素）。如果 `shots_per_run` 很大，这会非常贵。

但对远程纠缠实验来说，**只有 BSM success 事件的 qubit_state 才有意义**。你现在连非 success（例如 HOM 用的 H1H2、V1V2）也算 qubit_state。

建议：

- 默认只对 `sample.success == True` 的记录计算 `qubit_state`；
- 或者给个开关：`compute_state_for_non_success=False`；
- 更进一步：你已经有“枚举式”算 `fidelity_declared/fidelity_true` 的收缩（不需要 sample），同样可以枚举算 9 个 Pauli correlator（T_{ij}）并由此给出 CHSH，而不必对每个样本做 16 次收缩。

这样在不牺牲严格性的前提下，能把“抽样做 tomography”这个最耗时环节大幅削掉。

## 3) 关注点分离：你现在最大的结构问题不是“模块太多”，而是“接口语义漂移”

你其实已经做了一个很好的分层：

- `trajectory.py`：发射 + QFC/滤波 + fiber realization
- `gates.py`：各种局部门/BS/POVM
- `detection.py`：枚举/抽样/指标
- `mps.py`：MPS 操作 + contraction engine
- `common.py`：参数拼装/噪声预算/一次 trial 组织

问题在于：**“同名变量的物理语义”在不同层漂移了**，典型例子就是：

- `phase_jitter`: 在 fiber 侧被当成“每 bin realization 数组”，在 detection 侧被当成“std 标量”
- `p_bg_bin_map`: 在 common 侧是“探测器端概率 map”，在 detection 侧又被当成“源端 background map”再映射一遍

我的建议是：你把这些关键量做成**强类型 dataclass**，而不是 “tuple + dict + float 混用”。比如：

```python
@dataclass
class FiberRealization:
    U_A: np.ndarray
    U_B: np.ndarray
    eta_H_A: float
    eta_V_A: float
    eta_H_B: float
    eta_V_B: float
    phase_drift: float
    phase_slope: float
    phase_jitter: np.ndarray | None   # 如果用数组
    phase_jitter_std: float | None    # 如果用标量
```

然后在 detection 端明确只接受其中一种（数组或 std）。这样你以后加“相关噪声（OU）/慢漂移/随机游走”都不会把接口再弄乱。

## 4) 物理建模：哪些地方你已经做得“够真实”，哪些还缺，以及哪些简化可能让仿真失去指导意义

### 4.1 做得很好的点（保留）

- **把 fiber/BS/detector 统一推到 POVM**：这是非常对的，能极大减少“在态上做巨大 Hilbert 空间演化”的成本，而且理论上严格（用 𝔈† 作用到 effect）。这是很多 time-bin/MPS 方法的常见优化方向。([INSPIRE](https://inspirehep.net/files/ca191a3156bc35eb0ffaf2c5cc1fcd74))
- **区分 true success / false success（暗计数与背景辅助）**：你在 metrics 里把 `p_success_true`、`p_success_bg_assisted`、`p_success_intrinsic_dark_assisted` 拆开，试验上非常有指导意义。
- **用 `v_res` 做 indistinguishable vs distinguishable 的凸混合**：这是模型化“部分可分辨性导致 HOM 可见度下降”的标准做法。

### 4.2 可能“过度简化到影响指导意义”的点（需要你决定要不要补）

1. **光纤色散/PMD 没有显式建模**
   你目前 fiber 只做了：PDL（η_H/V）+ polarization rotation（Jones U）+ 相位漂移/斜率/抖动。
   但 16 km 量级的 SMF 在 1550 nm 附近色散大约是 ~16–17 ps/(nm·km) 量级，累积会影响波包的时间形状与相干时间窗口，从而改变“窗口扫描/最优 coincidence window”的结论（尤其你想把仿真用于指导 window 选取）。([Fiber Instrument Sales](https://www.fiberinstrumentsales.com/corning-smf-28-ultra-optical-bare-fiber.html?srsltid=AfmBOoprTwnK40Po7O0oTGwWcYqt2lGV60PbtteYLhA9Es9qO1Ysgtll))
   如果你的 1517 nm 光子谱宽较大（或 QFC 噪声谱宽/滤波不够窄），这一项不建会让窗口优化偏乐观。
2. **探测器时间抖动/jitter 没有显式并入 time-bin**
   SNSPD 的系统抖动可以做到十几到几十皮秒量级。([AIP Publishing](https://pubs.aip.org/aip/apl/article/109/15/152601/32196/Superconducting-nanowire-detector-jitter-limited))
   如果你用 dt=0.5 ns，jitter 会被完全吞掉（看起来影响不大）；但如果你在做“窗口扫描到几十 ps 量级”的优化（比如想用更窄窗口压背景），就需要把 jitter 作为时间卷积或在 click bin 上做随机偏移。
3. **背景噪声被当成“每 bin 独立 click 概率”**
   如果背景来自 QFC 自发拉曼/泵泄漏，严格来说它是“有谱密度的热光/泊松光”，并且在 BS 前后也会产生干涉/分束相关性。你现在的 OR 卷积相当于把它当成独立 classical click process。
   这在背景很低时足够；但如果你的实验进入“背景主导 false heralding”的区域，这种简化可能会把 `p_success_bg_assisted` 的尺度与窗口依赖搞错。
4. **发射模型中 cavity/atom 只允许单激发，这对单光子源是 OK 的，但无法预测多光子污染**
   你现在的原子能级结构与驱动只允许一次发射（|u>→|e>→|0/1> 后不会再被 drive 激发），因此 g^(2) 污染本质上为 0。
   如果你的实验里“多光子/双激发”是一个真实误差源（例如脉冲不理想、再激发概率非零），那你需要扩展模型（至少允许再次激发，或在腔/外场里允许两个光子子空间）。否则你会高估最终保真度上限。
5. **原子态制备/读出误差没进来**
   你现在主要在“纠缠生成阶段”加入噪声；但试验最终报告的 fidelity 往往还包含 state prep 和 readout 的 SPAM 误差。
   如果你的目标是“指导实验观测到的 fidelity”，最好把 SPAM 作为最后一个 classical channel（读出 POVM）也加进去；否则仿真会系统性偏高。

1. **Bell 投影的“误判矩阵”**
   你现在有 `p_success_true/false`，但实验上更关心的是：

- herald 为 Ψ− 的事件里，实际原子态投到 Ψ−/Ψ+/Φ± 的概率
- 以及相位漂移时 “Ψ− ↔ Ψ+” 的串扰
  这相当于输出一个 4×4 的 conditional probability matrix 或者至少输出 `⟨Bell_i⟩` 四个期望。

1. **MPS 数值可信度指标**

- 每步 `set_svd_theta` 的 truncation error（discarded weight）累计
- bond dimension 随 bin 的峰值/分布
  否则你很难回答“chi=50 够不够”以及“结果下降是物理还是数值”。

1. **相干可见度/HOM 可见度与各噪声参数的关系**
   你已经有 `hom.py` 和 `v_res`。建议输出：

- HOM visibility vs delay（或 vs `phase_slope`/`delay_jitter`）
  这能直接用来对齐/校准 `v_res` 的有效物理意义。

1. **把每次 trial 的随机 realization（fiber U、η、phase 参数）写到结果里**
   这样你后续做“同一组随机种子复现”或做误差归因会省很多时间。

## 6) 把单跑压到 ≤20 分钟：我给你一条“按收益排序”的优化路线

### 6.1 第一优先级（通常就是主因）：去掉 emission 循环里的全链 `canonicalize()`

- 把 loss Kraus 并入 bond θ 更新（2.1 的做法），从根上消掉每 bin sweep。
- 在 debug 下输出每个 stage 的 timing（你已经有 timings 字典），确认 emission 部分是否从 “>80% 时间” 降到合理水平。

### 6.2 第二优先级：修正 emission 的 swap 逻辑（否则后面一切优化都可能是在加速“算错的东西”）

按 1.1 + 1.2 修。

### 6.3 第三优先级：抽样阶段只对 success 事件算 `qubit_state`

- 如果你 `shots_per_run` 不大，这个收益不一定大；
- 如果你为了统计把 shots 拉到几千几万，这个是立刻见效的。

### 6.4 第四优先级：把 CHSH/相关函数改为“枚举式收缩”而不是“每样本 16 次收缩”

你已经能枚举 fidelity（靠 Bell projector left env）。同理：

- 为 9 个算符 `σ_i ⊗ σ_j` 建 left env
- 对每个 success pattern 累加期望
  最后由相关矩阵 T 算 CHSH（甚至算最优 CHSH）。
  这会比 Monte Carlo 更准确、还更快。

### 6.5 第五优先级（更大改动，但可能让你更稳）：把两臂发射拆开做，再在检测处合并

因为发射阶段两臂彼此独立，你现在用 interleave + 大量 swap 让结构复杂、也更容易出错。
如果你把 arm A/B 分开模拟，再在检测阶段用 POVM/收缩把它们“合起来”，代码更简单、也更接近物理分层；性能上通常也更好（少一半 swap、bond 结构更干净）。
但这属于架构重构，建议等 6.1–6.4 做完、并且结果与实验/基准一致后再动。

## 7) 最后：我建议你先做 3 个“快速正确性自检”，再开始大规模扫描

1. **零噪声极限**：关掉 fiber loss/PDL/相位噪声、暗计数/背景，`v_res=1`，看看：

- `p_success_true` 是否与理想 BSM 概率一致量级；
- `fidelity_true` 是否接近 1（或你理论期望的上限）。

1. **HOM 基准**：发射成完全相同波包、`v_res=1`、无噪声，看同偏振 coincidence 是否被压到理论极限。
2. **数值收敛**：把 `chi_max` 翻倍、`dt` 减半，检查关键指标变化是否在可接受范围内；同时输出 truncation error。
