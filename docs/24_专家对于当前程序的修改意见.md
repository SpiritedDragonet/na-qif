一、必须先修的“硬错误”（不修的话后面讨论任何噪声都没有意义）

1. `gates.py:jones_gate()`（以及 `jones_gate_from_array()`）两光子子空间的系数写错了，导致该门不是幺正
   你现在的 `jones_gate` 在 |2H>, |2V>, |HV> 子空间用了系数 “2*u00*u10” 这类写法。对于归一化的福克态基（你在 `operators.py:annihilation_op(SUBSPACE_1517)` 里确实是按归一化福克态来的），正确系数应当是 √2，而不是 2。

这一点非常关键：你在 `apply_fiber_channel()` 里把 `jones_gate_from_array(U)` 当作“幺正门”用 `apply_one_site_gate(... unitary=True)` 去施加；如果门本身不是幺正，MPS 的范数、后续的概率、以及任何基于干涉的物理量都会被系统性污染。换句话说：只要你开启了偏振漂移/相位漂移，这个错误会直接把结果带偏。

建议直接把 `jones_gate` 改成下面这样（只改两光子部分的系数即可；单光子部分你是对的）：

```python
def jones_gate(U: Tuple[Tuple[complex, complex], Tuple[complex, complex]]) -> np.ndarray:
    u00, u01 = U[0]
    u10, u11 = U[1]
    op = np.zeros((6, 6), dtype=complex)
    op[0, 0] = 1.0

    # 1-photon: |H>, |V>
    op[1, 1] = u00
    op[2, 1] = u10
    op[1, 2] = u01
    op[2, 2] = u11

    s = np.sqrt(2.0)

    # 2-photon: |2H>, |2V>, |HV>  (基：3->2H, 4->2V, 5->HV)
    # |2H> -> u00^2 |2H> + s u00 u10 |HV> + u10^2 |2V>
    op[3, 3] = u00 * u00
    op[5, 3] = s * u00 * u10
    op[4, 3] = u10 * u10

    # |2V> -> u01^2 |2H> + s u01 u11 |HV> + u11^2 |2V>
    op[3, 4] = u01 * u01
    op[5, 4] = s * u01 * u11
    op[4, 4] = u11 * u11

    # |HV> -> s u00 u01 |2H> + (u00 u11 + u10 u01) |HV> + s u10 u11 |2V>
    op[3, 5] = s * u00 * u01
    op[5, 5] = u00 * u11 + u10 * u01
    op[4, 5] = s * u10 * u11

    return op
```

你可以加一个单元测试（建议写进 tests 或至少写个 `__main__` sanity check）：

- 随机采样一个 SU(2) 的 Jones 矩阵 U
- 生成 `jones_gate(U)` 后检查 `||U6†U6 - I||` 是否 < 1e-12
  这个测试会立即把该问题钉死。

1. `gates.py:bs_gate_1517()` 的 50:50 分束器角度写错了（你现在等效是 85/15 的分束器）
   你用的分束器生成元是 `exp(θ (a†b - a b†))` 这种形式。这个约定下，模式变换是：

- a → a cosθ + b sinθ
- b → b cosθ − a sinθ
  所以 50:50 必须取 θ = π/4。你现在写的是 θ = π/8，并且注释里还说“50:50 => π/8”，这在你的生成元约定下是错的。

直观后果：单光子输入 |1,0> 会变成 cos(π/8)|1,0> − sin(π/8)|0,1>，也就是概率 0.8536 / 0.1464，而不是 0.5 / 0.5。对 BSM 成功率与保真度都会产生非常大偏差（尤其当你把它当“中心站干涉”用的时候）。

修复很简单：把 `theta = np.pi / 8` 改成 `theta = np.pi / 4`，并把注释改成“R = sin^2θ，50:50 对应 θ=π/4”。

如果你想保留“用户输入反射率 R”的接口，更稳的写法是：

- `theta = np.arcsin(np.sqrt(R))`
- 50:50 就是 `R=0.5`。

1. `trajectory.py:apply_780_filter()` 当前实现是“投影 + 归一化”的后选择，不是物理上的滤波损耗
   你目前做的是：对每个 bin 施加投影 `P = |vac><vac|_780 ⊗ I_1517`，最后整体 `renormalize=True`。这等价于“条件在所有 780 模式都为真空”这一事件上。对你这个流程来说，它实际上是在后选择“QFC 全部成功转到 1517 且 780 没残留”的分支，并把失败分支（未转成功的 780 光子）整段丢掉了。

这会造成两个严重问题：

- 转换效率（θ_H, θ_V）对最终总成功率几乎被抹掉，只剩下对态结构的影响；你得到的 `p_success_all / p_arrive` 会虚高。
- 对实验指导意义最重要的“链路预算”（QFC效率×耦合×光纤损耗×探测效率）在你的模拟里被人为拔掉一段。

如果你坚持用纯态 MPS + 量子轨迹来表示开放系统（你对光纤损耗已经这么做了），那么 780 滤波应当实现为一个 CPTP 的 Kraus 信道（把 780 子空间的 |H>,|V> 都阻断到真空），而不是投影后归一化。

最小改法（不改变你整体结构）：

- 用 `channels.loss_channel_both_subspaces(eta_780=0.0, eta_H_1517=1.0, eta_V_1517=1.0)` 得到 18×18 的 Kraus 列表
- 对每个 bin 调用 `mps.apply_kraus_one_site(site, K_list, rng)` 做一次量子轨迹采样
  这样每条轨迹都保持归一化，同时 780 光子被“物理地”吸收掉；留下的 1517 分支自然带着正确的成功概率权重。
- 之后再 `project_to_1517()` 把 780 维度丢弃就合理了（因为经过该信道后 780 一定在真空）。

如果你不想在这里引入额外轨迹噪声，也可以把 QFC+滤波整体等效成一个“把 780 单光子以概率 p 转到 1517，否则变真空”的幅度阻尼型通道（但这会牺牲你目前 QFC 的相干描述；是否接受取决于你是否需要保留 QFC 内部相干相位）。

1. `trajectory.py:run_dual_atom_emission()` 的时间索引与“从右到左交互 bin”的约定存在明显不一致风险
   你在发射里做了“原子从右向左扫过 bins”的 conveyor-belt，这本身是合理的。你也在注释里写“最后的 bin 对应最早发射”。但代码里：

```python
for n in range(n_bins - 1, -1, -1):
    time_idx = n
    gamma_A_n = gamma_A_values[time_idx]
```

这会把 `gamma(t)` 的时间序列按“空间 bin 索引 n”直接取值。若你的物理约定是“AN 是最早的时间片”，那 `time_idx` 应该是 `n_bins-1-n`（也就是你现在的时间序列被反过来用了一次）。

如果你目前主要用对称的 Gaussian（A、B 同 σ 且 t0 在中间）这件事在数值上可能没那么显著，但一旦你真的引入延迟、chirp、非对称脉冲整形或者更真实的控制脉冲，时间反向会直接改变波包、干涉可见度与 BSM 统计。

建议你明确一个唯一约定并写成代码常量：

- 约定 A1 是最早还是 AN 是最早；
- 然后用一个函数 `bin_index_to_time_index(n)` 统一转换，不要散落在循环里。

二、物理建模层面“缺的关键块”（补了才更像实验）
下面这些不是“必然要加”的全家桶，但如果你的目标是“对实验有指导意义”，它们里至少有几项会很快成为误差主导项。

1. 16 km 光纤对应的等待时间导致原子存储退相干（你目前完全没建模）
   16 km 单程传播时间量级是 ~80 µs（取折射率后群速度 ~2e8 m/s）。远程纠缠生成需要等 heralding 信号回来、做反馈/记录；对原子自旋来说，这个等待时间会把 T2/T2* 直接带进最终保真度与产率。

你目前的模型里，原子从发射到测量几乎没有“空等”，所以即便你把光学噪声做得很复杂，最终保真度仍会偏乐观。

推荐最小模型：

- 在“中心站测量发生前”对两个原子施加一个纯退相干信道：
  ρ → (1-p)ρ + p ZρZ（或更一般的相位阻尼 Kraus）
  其中 p = (1 - exp(-T_wait/T2)) 或按你的实验数据拟合。
- T_wait 至少包含：光子飞行 + 探测电子学 + 时间标记处理等。

1. 两光子干涉可见度（HOM visibility）/ 模式不匹配没有显式参数
   你现在的干涉“唯一影响”主要来自偏振旋转、相位漂移与时间 bin 对齐（而你还允许跨 bin 双击）。现实里最杀保真度的往往是：

- 两个光子频谱不匹配（中心频率偏差、线宽、chirp）
- 到达时间抖动与波包形状不一致
- QFC 引入的附加相位噪声/谱展宽
  这些会把 HOM 可见度 V 从 1 拉到 0.9、0.8 甚至更低，而对 BSM 输出的原子态保真度是线性/更快恶化的。

你可以用一个“有效 HOM 可见度”参数 V 来做最小封装：

- 在进入分束器前，对“交换两光子路径”的相干项施加去相干，使得干涉项乘以 V。
  实现方式很多，最简单的是在两光子子空间里对“可交换/不可交换”分量做相干衰减（等效 distinguishability channel）。这能让你把一堆复杂的谱/时域细节压缩成一个可测、可拟合的有效参数。

1. QFC 噪声（泵浦引起的噪声光子）没有建模，暗计数不足以替代它
   你把噪声主要放在探测器暗计数上，但在很多 QFC 方案里，主噪声是：

- 泵浦诱导的 Raman/scatter 在 telecom 端产生背景光子
- 泵浦泄漏、倍频/和频残留（取决于滤波）
  这些噪声会随泵浦功率、滤波带宽变化，且往往比 SNSPD 暗计数大得多，直接决定误报率与最优门限。

最小可用模型：

- 在 1517 每个 bin 上加入一个“背景热态/泊松”光子源（或更简单：以小概率 p_bg 在 H/V 两个偏振上随机产生单光子），然后让它走同样的光纤与探测流程。
  这会显著改变 `p_success_false` 的来源结构（不再只是 dark count），更贴近实验。

1. PMD / 色散你已经写了开关但没实现（`FiberChannelParams.pmd_enabled` 完全没用）
   如果你打算认真对待 16 km，PMD（偏振模色散）与色散导致的波包展宽、H/V 之间相对延迟，会直接影响有效干涉可见度。你现在的 `FiberChannelParams` 里有 `pmd_enabled`、`pmd_delay_bins`，但 `apply_fiber_channel()` 没有任何对应处理，这属于“代码看起来考虑了，但实际没起作用”的典型陷阱：建议要么实现，要么删掉避免误导。

三、一些“过度简化到会误导实验”的点（建议你至少明确它们的适用范围）

1. `apply_780_filter` 的后选择（上面已说）会把 QFC 效率从链路预算里移除，这是最危险的简化。
2. 分束器只做“同一 bin 的 A_n 与 B_n 干涉”，但你又允许“跨 bin 双击也算成功”
   这两者叠在一起会出现一个逻辑不闭合的问题：你在动力学里假设不同 bin 是正交模式（这在 time-bin 离散化里是对的），那么跨 bin 的两次点击本质上是“两个可区分的时间模式”上的探测事件，通常不会产生你想要的 Bell 投影（或至少会带来额外的相位/权重结构）。你目前 `check_bsm_success()` 默认不加时间窗，相当于在“只按探测器组合，不按到达时间”做粗粒化 heralding。实验里通常会有 coincidence window（或甚至严格同一 time tag）来定义 BSM 成功。

你已经提供了 `window_bins` 参数，但 `total_simulation.py` 里枚举与采样都没用它。建议你至少做两套指标：

- 严格同 bin（或 ±1 bin）窗口：更贴近 HOM 干涉定义
- 宽窗口：对应“只看 detector pattern”的粗粒化
  然后对比两者的 `p_success` 和 `fidelity`，你会很快知道时间选择对实验优化到底有多关键。

1. 发射波包整形：你用 `gamma(t)` 直接取 Gaussian 不一定对应 Gaussian 光子波包
   在输入输出理论里，输出场包络与耦合/控制脉冲之间不是简单的 “波包 ~ γ(t)”。如果你要用模拟指导实验的脉冲整形，建议用两步走：

- 先从实验测得的光子时间分布拟合出有效 `gamma(t)`（或更直接：把发射模型升级为“原子+腔模”显式系统，再由控制场驱动）
- 或者至少做 `dt`、`n_bins`、`chi_max` 的收敛性检查，避免把离散化误差当成物理效应

四、关注点分离与工程结构（哪些地方“废弃/该减掉”，以及怎么重构更稳）

1. 最该拆的边界：物理模型 vs 数值引擎 vs 实验脚本
   目前 `total_simulation.py` 同时承担：

- 参数采样/随机种子管理
- 物理流程编排（发射/QFC/光纤/BS/探测）
- 大量诊断打印、画图、写 CSV
- 并行执行框架（`ProcessPoolExecutor`）

建议把它拆成三层：

- `model/`：门与信道（`gates.py`, `channels.py`），只提供“给定参数->矩阵/Kraus”
- `engine/`：MPS/TEBD 更新（`mps.py`, `trajectory.py`, `detection.py`），只负责“给定门/信道->更新态/求概率”
- `experiments/`：具体实验流程与输出（现在的 `total_simulation.py`）

这样你以后加一个新噪声（比如 QFC 背景光子）不会把顶层脚本写成泥球。

1. 可以认为“已经废弃或至少应该降级为可选”的代码块

- `detection.py` 里 18D 探测 Kraus 分支：如果你流程中总是 `project_to_1517()` 后再做 BS 和探测，那么 18D 探测可以保留作 debug，但默认路径应该只走 6D（否则计算量暴涨且容易引入不一致）。
- `FiberChannelParams` 的 PMD 相关字段：目前没用。要么实现，要么删掉或明确标注 “TODO: unused”。
- `total_simulation.py` 里大量重复字段的 `SUMMARY_HEADER`（`success`、`p_arrive` 等出现多次）：这属于纯维护负担，建议清理。

1. 数值性能上最明显的“关注点混乱”

- `apply_kraus_one_site()` 每次都会 `canonical_form_finite(renormalize=True)`，这相当贵；你在光纤损耗里对每个 bin 都调用它。短链还好，但一旦你把 n_bins 拉到更真实的波包长度，这会成为瓶颈。
- `run_two_photon_detection()` 每个 bin 都 `canonical_form_finite` 再取 rho，再采样 Kraus。你已经在 `apply_two_site_kraus(... probs_from_rho=True)` 上做了避免正交中心依赖的设计，但前面这次全链 canonicalization 仍然很重。更“TEBD 风格”的做法是：把正交中心移动到当前 bin 对附近，再局部计算 rho/更新，然后把该对“冻结/截断”（你在 `MPSState.finalize_bin_pair()` 已经写了思路，但没有在探测流程里用起来）。

建议你先不急着极限优化，但至少把“检测后冻结 bin 对”的逻辑接上；这会让复杂度从潜在的 O(N^2) 更接近 O(N)。
